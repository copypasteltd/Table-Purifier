## 首个纵向切片

使用合成报价资料：创建任务→上传/文字→预检/范围确认→明确免费许可→DISCOVER全范围规范（保留稀有保修字段）→用户采用→提取/独立验证→待议价格问题→人工决定预览/提交→child Run→9文件回读/发布→手机实际取用。然后同数据走 PROVIDED，对比规范遵循/模板样例不入事实。

切片允许先固定一种获证输入格式，但必须注明未完成格式/OS/通道；它证明架构连通，不等于38项P0全部完成。不要先把18页填成静态成功图，再补后端事实合同。

## 需求覆盖与任务验收

backlog 从当前42需求/53API/18页反向生成映射并追加横切任务。P1任务状态 PARKED_P1，P0不依赖P1完成；API38跨端绑定可选，但P0身份不误合/付费权益边界必须测试。每个任务引用具体AC/E/NFR并有独立验收文字，禁止只写“完成接口/页面”。

完成定义：代码/迁移与锁文件在位、相关测试真实执行、有安全/异常恢复行为、共享合同/页面B状态一致、文档和配置变化同步、无敏感数据提交、验收证据能对应build/环境/版本。若只有接口stub或fixture，标 STUB/SYNTHETIC，不关闭需求。

## 提交、审查与变更

功能按领域小步交付：先合同/迁移，再service/adapter和相关测试，最后双端视图。PR描述触发场景、变化和验证；资金/权限/轮次/不可变变更明确事务与竞态。review检查模板事实污染、隐藏截断、枚举漂移、P1误开、未核SDK调用和日志泄露。

需求改动更新v3.1后续版本和追踪，B视觉改动建新设计版本，开发技术变动写ADR/迁移/回归。冻结B和v3.0快照不覆写；历史ZIP/报告保留真实时间与范围。开发基线独立manifest记录依赖业务hash，后续基线变动时先评估兼容再更新指针。

## P1 接缝

Web复用领域API/DTO，但有自己的可信登录/权限/工作台、跨端绑定挑战，不能靠同手机号自动共享资料；首版手机流程不能依赖Web完成。

增量协作需要新source_set/contract与权限模型，不能原地追加旧已付范围；复杂多表/音视频等要新格式/计量/质量/售价合同；开发者异步付费API/Machine Pay需scope、幂等、授权支付、结算和赛事认可独立证据。P1现阶段只留契约/开关，返回受控不可用，不伪造可调用能力。

## 交接包

开发交接至少包含本文档索引、OpenAPI/传输合同、DB目录/参考DDL、配置schema/示例、backlog、页面组件映射、pipeline、外部证据register和静态核验报告。后续实现交接再增加源码/lock/正式迁移、真实测试/平台证据、release manifest和演练记录。本次ZIP包含文档与参考资产，不包含runtime、依赖、客户内容或商户秘密。

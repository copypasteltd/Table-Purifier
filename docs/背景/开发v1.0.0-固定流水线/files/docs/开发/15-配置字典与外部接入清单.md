# 配置字典与外部接入清单

P07-DEV 1.0.0｜业务 v3.1｜配置合同草案，尚无应用读取器。

## 配置来源与校验

默认配置→环境配置→显式secret reference的覆盖顺序固定；启动时按[config.schema.json](../../assets/development/v1.0.0/config.schema.json)验证并运行跨字段guard。环境名 development/test/staging/production，不由客户端决定；路径解析后必须仍位于项目 runtime。生产禁止 fixture provider、http公网、默认秘密、公开objects和未验能力。

[config.example.json](../../assets/development/v1.0.0/config.example.json)仅含示例非秘密，收费和全部平台能力默认关闭，external provider disabled。它能通过配置结构校验，不代表能启动完整服务。数据库连接串/商户/OCRkey从runtime/secrets的受控ref解析，不得把占位字符串当真实密码连接。

| 分组 | 关键键 | 实现约束 |
| --- | --- | --- |
| app | id/version/environment/business_baseline/design_baseline | 与release manifest一致；未知基线拒绝启动 |
| paths | runtime_root/object_root/scratch_root/log_root | 解析/realpath后严格在runtime，拒绝重解析点逃逸 |
| http | host/port/public_origin/trusted_proxy | 本地默认loopback；生产HTTPS、可信代理名单 |
| database | connection_secret_ref/pool_max/statement_timeout_ms | 每事务owner上下文；禁止默认超级用户 |
| worker | lease_seconds/heartbeat_seconds/poll_ms | heartbeat < lease/2，fence全写核验 |
| budgets | 原件/单元/字段/候选/compute/retry | 不超已确认合同上限；不能靠客户端改数 |
| preflight | semantic_units_max/new_tasks_per_day | 最多3单元/每日5新任务候选口径 |
| export | download_ttl_seconds/page_size/page_size_max | 300秒候选、20/100分页；不可撤长期URL禁用 |
| providers | ocr/model/payment | disabled/fixture/approved，production禁fixture |
| commerce | enabled/approved_sku_ids/policy_snapshot_id | enabled必须真实审批/四环境/SKU证据匹配 |
| policy_candidates | review_hours/revision_rounds/retention_days | 24/2/7仅候选，不能直接对外作权益 |
| features | 双平台四环境flags、P1开关 | 默认全false，服务端关键动作重核 |
| observability | log_level/redaction/enabled_metrics | 不提供正文debug开关；日志不含query/token |

跨字段检查包括：approved provider 必须有合规/秘密refs；enabled收费至少一个获准SKU且生效policy；下载期限/数据期限与原合同相符；所有runtime子路径合法；heartbeat与lease关系；全局预算不能静默收紧已售合同；接口能力flag打开必须引用当前build/app/OS/SDK真实证据。

## 外部接入关闭条件

[integration-register.json](../../assets/development/v1.0.0/integration-register.json)逐项记录责任W、阻断范围、证据类型、当前NOT_RUN/UNVERIFIED和关闭条件。必须区分以下事实：

- 工具已安装、工程能编译、模拟器能调用、四环境真机成功，是不同证据。
- 平台有公开API、当前主体获准、目标SKU/OS可售、实际原路退款完成，是不同证据。
- 模型能返回JSON、数据合同允许外发、事实质量达标、费用可控，是不同证据。
- 生成文件、临时缓存、可打开、用户可见导出、平台商品认可履约，是不同证据。

每次接入记录官方链接/读取日期、实际 SDK/package 版本、app_alias/环境、最小复现、请求/响应脱敏样本、错误/重试/限流、费用/隐私、测试结果/时间/执行者和build。真实商户材料/凭据在runtime，不放公共register。

## 可提前确定与必须实证的分界

已选：原生双端、Node/Fastify/PostgreSQL/Python、无虚拟化、DB可靠队列、不可变版本、服务端交易事实、B样式变量、owner隔离、9文件与模型无工具权限。

待实证：各端文件选择/打开/实际导出、最低SDK/开发工具版本、目标主体与商品/支付/退款、精确依赖patch和PDF renderer、OCR/模型合同与性能/成本、正式域名证书/Windows服务wrapper、RLS/资源限制/备份恢复的真实效果。待实证并非重新询问用户许可；开发可做不依赖它们的工作，相关生产开关保持关闭。

## 配置变更与版本

配置schema/默认值有独立config_version；向后兼容新增先以关闭默认落地。policy_snapshot绑定原contract，不能因全局改24→12就缩短已售窗口。capability更新生成版本和审核事件，消费者读旧缓存也不能绕开服务端新禁用。

回退按旧代码支持的schema运行，迁移字段采用expand/contract；秘密轮换与代码回退分离，不能恢复已泄露旧key。每次变更记录影响范围、测试、回退和监控；灰度期间费用/未知款/取用/删除告警必须可按配置版本分组。

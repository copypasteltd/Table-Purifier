# 任务队列与并发恢复

P07-DEV 1.0.0｜业务 v3.1｜可靠性实施合同，未测试。

## Job、Run 与 Attempt

Run 是用户合同的一次执行，不是进程。Job 是可投递的阶段工作；Attempt 是一次持租约执行。Job 重领不重建 Run，修订才创建 child Run。工作流见[pipeline-contract](../../assets/development/v1.0.0/pipeline-contract.json)，正交业务状态仍以 [domain-contract v3.1](../../assets/contracts/domain-contract.v3.1.json)为准。

Run 阶段按 scope/模式决定：PARSE → ANALYZE → PROPOSE（DISCOVER，进入 WAITING_SCHEMA）→ EXTRACT → VALIDATE → BUILD → PUBLISH。PROVIDED 使用已明确采用/绑定规范；DISCOVER 未 FULL 采用不得跳 EXTRACT。预检是独立受限 job，不调用完整免费整理；预检语义分析最多 3 单元。

## 领取与租约

job 使用 READY / LEASED / DONE / DEAD 内部状态，不混入 Run 执行轴。事务用 `FOR UPDATE SKIP LOCKED` 领取 READY 且 available_at 已到的行，更新 lease_owner、lease_until、递增 fence，再建立 stage_attempt。领取返回 run_id/owner_id/input_hash/budget_ref；worker 重新校验许可、删除、当前 Run/fence。

初始工程值：lease=60 秒、heartbeat=15 秒、队列空闲 poll=2 秒；这些是运行参数，需压测/故障注入后调整，不是对用户 SLA。DB 时间为准；heartbeat 只以 job_id + lease_owner + fence 条件续租。续租失败停止新外部调用/子进程，不能靠本机时钟自行延长权利。

阶段完成条件 UPDATE 同时核 `fence=current`、Run 仍 RUNNING、task epoch/current pointer、无 tombstone。旧 worker 即使后来返回成功，也只能写 attempt 的隔离诊断，不能提交结果/消费轮次/发交付事件。安全的确定性解析可复用同 input_hash+parser_version 的检查点，但仍重新授权。

## 检查点与幂等外部调用

每阶段保存 input/output hashes、parser/OCR/model/prompt/rule 版本、source_set/binding、对象引用、coverage、计量和 attempt_id。输出先写 staging，对象完成/校 hash 后短事务引用检查点；文件写了而数据库没提交为 orphan，恢复扫描回收。数据库已引用对象却丢失是内容损坏，不返回假成功。

外部调用先持久 provider_request_id、意图、预算预留；供应商支持 idempotency 则使用稳定 key，超时先按同 request_id 查询。供应商不支持查询/幂等时，超时标 UNKNOWN，不能自动重发并声称一定只付一次；按预算/内容风险选择安全失败、人工确认或显式批准的重试。重试成本同样累计，不能只记最后成功 attempt。

## 预算算法

processing_contract 固定最大文件/字节/单元/字段/候选和计算上限；run_budget_events 对 root/child/retry 按同 contract 记事件、唯一 event_key。累计计算以实际活跃阶段 wall time（含等待外部模型/OCR响应及解析/构建）为口径；排队、等待用户采用/决定不计。不能同时对并行阶段 wall time 和其总时长重复计量；P0 每合同同一时刻只允许一个活动计算 lease。

每次阶段启动原子校剩余额度，设置最大 deadline；heartbeat 分段追加累计毫秒，最终关闭补齐尾段，崩溃按最后心跳到 lease 失效的保守预留封顶结算并记估算来源。重领先结清旧预留，再继续，不能重置 900 秒。租约/预算消耗唯一键避免双扣；发布也受同 contract 预算与取消/删除守卫。

本轮细化选择累计实际服务计算时长作为 900 秒的实现口径；外部费用另按 token/OCR 单元/流量记录。W01 用真实供应商响应时间验证此口径可履行，并让报价/告知明确；若需要改口径必须变更合同版本，不能对已售单追溯收紧。

自动阶段重试最多一次，仅对明确临时错误/安全幂等阶段；错误分类为 RETRYABLE、PERMANENT、UNKNOWN_EXTERNAL、USER_ACTION、BUDGET_EXCEEDED。XML 畸形/密码、缺规范采用、未知付款/退款、无证据事实不能作为普通 transient 自动重试。

## 取消、删除与发布竞态

1. API30 锁 task/run，校 expected_run_version。尚非终态时登记 cancel_requested + version/epoch 变化；撤新计算权，创建 operation。取消先胜则旧 worker 的 publish 条件失败。
2. publish 事务锁同一 task/run。若先完成 READY/结果/Run终态，后取消返回已完成事实，不强改历史 CANCELED；售后另走原合同。
3. 删除先写 tombstone、revoke future grants、bump epoch，worker 每阶段/发布前再核；发布与删除锁同一聚合保证不出现“删除后旧 worker 重新开放”。
4. 实际进程已向外部发出的请求和已发送下载字节无法撤回；登记供应商删除请求/停止后续使用，不写“全部副本即时消失”。

运行中的原文件移除不是简单 DELETE source；冻结后需要新范围/合同版本，旧已付合同按履约和退款规则处理。

## Outbox 与定时任务

业务事实和 outbox_event 同事务提交；dispatcher 领取未发送事件，用 destination + event_id 去重。接收者的 inbox/事件唯一键保证重复投递不产生重复退款、通知或清理。发送成功但确认丢失会重投，不能宣传 exactly-once 网络投递。

scheduler 自身也用 DB lease，重复实例不会并发执行同周期对账。职责：回收过期 job、付款/退款 UNKNOWN 查原单、quote/upload/download 到期、artifact/源内容清理、orphan/临时文件回收、删除失败重试、每日对账和运营未决提醒。具体周期考虑平台限流，不固定成未验证外部 SLA。

## 崩溃恢复验收表

| 故障点 | 预期恢复 | 不允许 |
| --- | --- | --- |
| 业务提交后 API 响应丢失 | 同幂等键/operation 找回 | 多建 task/order/child |
| 收到付款后 job 投递前断电 | 同事务 outbox/job 仍可发送 | 已付但永久无执行/售后 |
| 模型返回后检查点提交前崩溃 | 查 provider request 或安全失败/重试记录 | 不记费的无限重发 |
| 心跳失效旧 worker 回来 | fence 拒绝其写入 | 覆盖新结果 |
| 决定提交后手机退出 | batch/reserve/child 持久、查 operation | 第二次扣轮次 |
| 八个文件已写第九失败 | 不 READY，半包隔离 | 返回半套成功 |
| 取消/删除与 publish 并发 | 唯一可解释胜者、审计 | 删除后重新签链 |
| DB 短暂断连 | 停止授权写、依 lease 退出/恢复 | 用内存状态假确认付款或交付 |

这些必须用真实 PostgreSQL、进程终止、网络超时和重复事件测试，静态状态图不构成通过。失败重试耗尽转 DEAD/运营待办；人工重跑仍要新 Attempt/操作、权限/预算和审计，不直接改数据库终态。

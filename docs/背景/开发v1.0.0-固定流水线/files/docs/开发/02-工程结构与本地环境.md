## 首次 bootstrap

1. 在项目根确认父级/本级 AGENTS、需求和设计 active 指针。检查 Python/Node/pnpm 路径与版本，列明未安装项；不调用任何虚拟化服务。
2. Windows 原生 Node 24 LTS、PostgreSQL 18 安装包/免安装分发及文档下载到 runtime/tools；校官方签名/摘要和许可证。用户级/系统级安装是否必要在具体实施时判断；优先项目局部运行时，不覆盖全局 Node 22。
3. 设置当前进程级缓存/TEMP 到 runtime，避免正文/构建临时文件散落系统临时目录。不要修改 HOME/CODEX_HOME 或全局安全软件设置。
4. 建立根 workspace、src/api 和共享逻辑 package；精确 packageManager、engines、依赖和 pnpm lock。锁 TypeScript/插件后检验两个宿主输出，无需默认最新主版本。
5. `python -m venv runtime/venv`；引擎锁文件带精确版本和哈希，用 `python -m pip` 定向安装。验证 import、XML 防护、PDF 渲染、CSV 日期/数值回读。依赖缓存和 wheel 放 runtime。
6. 初始化独立开发数据库，数据目录 runtime/db；创建 migration_owner、p07_app、p07_worker、p07_readonly 四类角色。仅监听 loopback，秘密放 runtime/secrets，使用受控配置注入。
7. 从参考 DDL 拆正式迁移并在全新 PostgreSQL 实例执行，再跑迁移升级/回退与事务测试。**不能直接对真实业务库运行参考 SQL。**
8. 配置 disabled/provider fixture 模式，启动 API、Worker、scheduler；合成纵向测试通过后再接正式服务。将构建版本/命令/硬件写入 runtime/evidence。

下列 PowerShell 仅是本地环境准备范例，使用现有 Python；不代表目标 Node/数据库已就绪：

```powershell
Set-Location -LiteralPath 'E:\dev\sandbox\支付宝黑客松\表格修复站'
$p07Root = (Get-Location).Path
$p07Dirs = @('runtime/pip-cache','runtime/npm-cache','runtime/pnpm-store','runtime/scratch')
$p07Dirs | ForEach-Object { New-Item -ItemType Directory -Force -Path $_ | Out-Null }
$env:PIP_CACHE_DIR = Join-Path $p07Root 'runtime/pip-cache'
$env:npm_config_cache = Join-Path $p07Root 'runtime/npm-cache'
$env:TEMP = Join-Path $p07Root 'runtime/scratch'
$env:TMP = $env:TEMP
python -m venv runtime/venv
```

缓存和临时变量只针对当前终端/服务进程；关闭终端后重新注入。项目 `.npmrc` 应显式指定 runtime/pnpm-store；业务内容不得落入可提交的包构建缓存。正式服务也要设置自己受控的 TEMP。

## 进程和端口规划

| 进程 | 开发默认 | 行为 |
| --- | --- | --- |
| API | 127.0.0.1:7307 | HTTP 开发入口；真机经受控 HTTPS 域名，不随意暴露局域网 |
| PostgreSQL | 127.0.0.1:5437 | 专用开发实例；端口冲突显式改配置 |
| Worker | 无公开监听 | 轮询 DB 队列，执行引擎/模型、产生检查点 |
| scheduler | 无公开监听 | 有数据库租约的定时补偿、到期/清理/对账 |
| Python 引擎 | stdin/stdout 控制协议、文件对象 | 每个 Attempt 独立受限进程，不启动公开 Web 服务 |

小程序不能把手机的 localhost 当后端。真机使用经过平台域名白名单/证书验证的 HTTPS 测试环境；调试器临时放开网络限制不算正式可用。开发机网络穿透如需使用，也必须锁目标/认证/有效期，不能把数据库或 objects 目录公开。

## 工程约定

HTTP 字段 snake_case，TypeScript 内部可 camelCase，边界转换只做一次；枚举与字段 ID 取自合同，不在手机散布字符串判断。时间传 UTC ISO8601，数据库 timestamptz；用户展示按明确 timezone，不能由 Windows 本地时区隐式解释。

用户可见文本集中管理、错误码稳定。密钥不写入 app 工程、日志、assets 或构建。数据 ID 随机 UUID，不以路径/文件名作为授权。提交前敏感扫描、lint/类型/相关测试、文档引用校验；构建输出/依赖/runtime 不进入版本库。真实截图提交前去除标识与签链。

依赖升级以独立变更记录许可证/安全/宿主兼容，重跑受影响格式和四环境；Python 或 Node 大版本变动重跑原生 wheel/打包/子进程退出测试，不自动跟随 latest。

## 文档工件的复核环境

本次仅在 runtime/tools/document-validation 安装文档校验工具，未安装应用运行栈。精确版本见[工具链记录](../../assets/development/v1.0.0/validation-toolchain.json)及[固定版本列表](../../assets/development/v1.0.0/validation-tools.requirements.txt)。复核需原生Python及已有设计校验器的Pillow；缓存/TEMP按上文定向runtime。

工件再生成顺序为 `build_development_assets.py` → `build_development_openapi.py` → `build_development_contracts.py`。审阅差异后用 `seal_development_baseline.py --seal` 更新开发hash，再运行 `verify_development_docs.py --report`；seal只允许维护原需求清单内README/AGENTS导航hash，其他业务内容变动会拒绝，不能用它隐藏需求改写。生成器不连接数据库、宿主或供应商。

完整OpenAPI、JSON Schema及SQL语法检查用于发现文档错误；正式迁移/RLS、进程资源限制、内容精度、支付和真机仍需按测试计划执行。

# 表格修复站：验收测试与实施计划

> 历史基线v1.0：2026-10-27已由“多源资料按规范表自动成表”的v2.0替代，仅作历史记录。当前需求见 [PRD](../../01-产品需求PRD.md)。

P07｜v1.0｜待执行验收，不代表软件已实现。P0 及 C-T01—C-T10 是收费上线条件；P1/P2 在扩展发布前验收。

## 标准答案集

使用完全合成或取得测试授权的数据，至少覆盖：UTF-8/BOM/逗号和引号、多行单元格、空白行、同名列、0/1/1000/1001 条记录、5 MB 边界、20/21 列、公式带缓存、宏/加密/坏包/解压炸弹；文本 000123 与 20 位订单号、已损坏科学计数、歧义日期和两个 Excel 日期系统；千分位/小数点混用、多币种、超精度、缺失币种、优惠运费导致实付不等于单价×数量；同单多商品、整行重复候选、明确移出；危险 CSV 文本与真实负数。

每个样本预先人工写明规范值、三类行去向、问题码、变更与分组金额，不能把当前实现输出直接当标准答案。至少 5 个用户目标模板做真实导入验证，不只验证“文件能打开”。

## 两周实施计划

| 阶段 | 交付 | 门槛 |
| --- | --- | --- |
| 第 1–2 天 | 真实目标系统、用户访谈、标准表和目标 schema、支付申请与 SDK 契约实验 | 先证实导入需求与 D02，不确定项写清，不在付费后发现不支持 |
| 第 3–5 天 | 安全解析、规则引擎、源坐标、分类、变更和守恒 | P07-T02/T07—T14 标准答案全部通过 |
| 第 6–8 天 | 诊断/确认网页、业务 API、报价、Machine Pay、幂等 | 实际沙箱跑通，重试不重复收费 |
| 第 9–11 天 | 任务恢复、结果权益、取消/退款、清理/后台/成本 | 故障、租户隔离、退款与恢复演练通过 |
| 第 12–14 天 | 真实模板导入、P0 回归、小规模真实购买和回访 | P0/C-T全通过、外部资质到位、准确披露未解决项 |

估计适用于 1–2 名熟悉 Python 数据处理与支付开发者，不包括外部审批、访谈招募和新增领域。未能在同步协议时限内完成上限文件时，先调整 SKU 范围并重新冻结报价，不以超时后偷偷扣款解决。

## 发布与事故处置

交付源码、规则目录与锁定版本、API 使用示例、合成数据和预期报告、原生启动/备份/恢复脚本、支付适配配置说明、内容清理任务、对账与客服手册。发现数据转换错误时先关新增任务、定位规则版本和受影响订单，保留原合同与更正记录，再纠错/退费。只有实际验证的目标系统可列为支持，不把任意 CSV 可导出等同任意业务系统可导入。

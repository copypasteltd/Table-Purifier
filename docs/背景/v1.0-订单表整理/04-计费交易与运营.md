# 表格修复站：计费、交易与运营

> 历史基线v1.0：2026-10-27已由“多源资料按规范表自动成表”的v2.0替代，仅作历史记录。当前需求见 [PRD](../../01-产品需求PRD.md)。

P07｜v1.0｜价格和规则为实验设计，不代表已售服务。

## 服务与定价

SKU `P07-ORDERS-1000-V1`：5 MB 内一个 CSV/XLSX 值表，最多 1,000 条记录、20 列，使用一个已确认目标模板和规则集，交付导入表、待确认/移出表、变更明细和校验包。测试价 190 分 CNY/任务。相同任务的网络重试、状态查询和 7 天内领取不收费；换源文件、选表、映射或规则为新合同，先报价再执行。

不按“修好多少格”浮动收费，不在处理后增加费用。免费诊断限额、模型脱敏范围、可能剩余 pending、CSV 安全转义影响和不支持公式，均在支付前说明。用户选择将已知问题列入 pending 后，系统按合同交付不等于承诺所有行均可导入。

## Machine Pay 业务闭环

使用 [Machine Pay 官方产品](https://aipay.alipay.com/products/machine-pay) 实际获准 SDK。步骤为：确认合同 → SDK 提示付款要求 → 用户/Agent 按授权预算付款 → 服务验付并按协议执行/结算 → 结果领取。具体时序先完成 D02 验证；业务 API 与官方付款协议分层。

Agent 的调用授权应限制服务、最大单笔金额与有效期；平台不能凭第一次授权任意提高单价。没有公开确认的预算授权能力时，用逐笔明确授权，不能臆造“免密无限扣款”。单笔金额或规则变化都产生新确认。

| 事件 | 收费/退款决策 |
| --- | --- |
| 预检拒绝、未确认规则、免费诊断失败 | 不收费，返回具体原因 |
| 支付未知或凭证未确认 | 不公开付费结果，先查原交易，避免重复付款 |
| 同键同请求重试、同任务轮询下载 | 返回已有状态和权益，不重复收费 |
| 同键换文件、换规则、换租户 | 拒绝冲突，不擅自执行新收费 |
| 约定 pending 正确单列、完整报告生成 | 正常履约；页面不能写“全部修复成功” |
| 行丢失、金额精度错误、报告缺失、文件不可读 | 平台失败，有限重试，无法修复退实付或释放尚未结算授权 |
| 用户上传源数据已丢失数字 | 预先告知无法恢复；不伪造修复，不因用户付款而补造 |
| 用户要求换规则重新清洗 | 展示新报价；平台程序错误的纠错免费，不与新需求混同 |
| 可履约后 2 分钟仍未形成完整结果 | 终止新尝试，进入失败处置；退款/释放结果可查 |

原支付号和退款号按唯一约束处理，不通过重复创建退款“碰运气”。如果完成计算但结算失败，保留短期产物进行恢复，记录平台未回收成本，不把未收款计作收入。

## 成本、报表与指标口径

单笔贡献＝净收款－全部诊断与映射分摊－文件处理－存储下载－通道费－失败重试与售后。人工支持成本单列，若每单需要客服解释大量表格规则，1.9 元方案很可能不成立。0.3 元和 1 元变动成本时贡献分别为 1.6 元、0.9 元，纯为示例；真实成本用全量任务日志与账单核算。

报表分开列：有效付费租户、去重付款者、任务数、调用次数、退款数/金额、完整交付率、存在 pending 的任务比、目标导入反馈、平均人工时间、单位贡献。企业一名付款者调用 10 万次，不能记为 10 万名付费用户；参赛统计按官方实际口径核验。

## 运营与支持

后台可按任务查合同、三类记录数量、规则/引擎版本、费用、耗时和错误码；默认不展示原始单元格。客服若需查看原表，在保存期内取得授权并审计；超过原表保存期请用户重新提供，不能声称仍能看到已删文件。

规则版本发布需要标准答案集和回归报告；发现数据损坏立即暂停该版本的新报价，定位受影响订单并联系用户（实际发送须另有明确授权），免费重做/退款。历史报告和账务不覆盖，发布更正版本并说明差异。

获客先选一种明确目标系统，提供一份公开合成脏表和可复制的调用演示，让用户验证目标导入。客户数据不得为宣传便利而公开。反馈不与点赞、付费统计或退款挂钩。

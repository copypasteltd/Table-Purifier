## 问题与定位

小电商运营、代运营和工作流开发者，需要把来源各异的订单表导入某个确定的管理系统。列名、字段类型、日期、币种和重复候选导致导入失败；纯手工修表难复用，自由生成式改表又难证明是否漏行或改错金额。

本产品交付“按已确认规则转换的数据＋未解决问题＋逐项变更与校验”。核心为 Agent/工作流可按需付费调用的 API，配薄网页供运营确认。价值在于可追溯、可复用、可导入，需求成立与否以真实目标系统的导入结果和省下的时间验证。

用户故事：“我愿意明确目标格式和歧义规则，希望系统把能证明正确的转换做完，把无法确定的记录单列，并解释每次改动，不能为了看起来干净就删除订单或编造缺失值。”

## 用户、权限与使用边界

运营上传并确认文件；租户管理员管理模板和 API 密钥；Agent 按授权的模板、规则与预算发起调用；客服只看必要状态；财务对账，不看原始订单正文。所有上传、规则、任务、结果都按租户隔离。目标系统不授权时，首版只导出，不替用户写入外部系统。

首版领域为订单明细值表，目标字段默认：订单编号（文本）、下单日期（日期）、商品名称（文本）、数量（十进制/按模板约定）、实付金额（十进制）、币种。模板明确必填、允许缺失、精度和目标导入规范；不同语义金额列不能混成一列。

## 输入与输出合同

输入：CSV 或 XLSX，单次一个文件，选择一个工作表，一行表头；1–1,000 条非空数据记录、最多 20 列、5 MB。纯空白行不算数据记录，但诊断报告列出位置与数量；没有数据记录的空表不报价、不收费。宏文件、公式单元格（即使有缓存值）、密码文件、复杂合并表头和超过限制的内容在付费前拒绝。CSV 首版支持 UTF-8/带 BOM；其他编码需用户重新导出或在后续版本显式支持。

| 产物 | 用途 | 保证边界 |
| --- | --- | --- |
| importable.xlsx / importable.csv | 只含确定可导入记录，按所选目标模板 | 不声称未解决记录也已修复；CSV 导出安全转义可能影响特殊文本，预先提示可改用 XLSX/JSON |
| pending.xlsx / pending.json | 待确认记录与原因/建议 | 保留源行定位和原始值，不猜填 |
| excluded.xlsx / excluded.json | 用户明确移出的记录与理由，允许为空 | 不静默删除，不把重复订单号自动等同重复行 |
| changes.jsonl / changes.xlsx | 每项变更、规则、原值、新值与坐标 | 只记录实际发生的变换和导出转义 |
| validation.json、manifest.json、说明文件 | 行去向、分币种金额覆盖、规格哈希、版本 | 验证转换一致性，不证明原始订单事实真实 |

结构化 JSON 保存规范业务值；CSV 若需公式防护前缀，必须在报告中披露与原规范值差异，不能以“金额/ID 无损”掩盖导出格式差别。首版全部交付物形成一个包，包含原值的报告按结果保存期保护。

## 业务原则与范围

P0：文件预检、单表/表头选择、免费诊断、受限脱敏 AI 映射建议、用户确认、确定性规则、ID/日期/金额保护、重复候选与行分类、逐项审计、导出校验、确定报价、真实 Machine Pay、持久任务和免费重领、失败退款、数据清理和运营。

AI 负责语义建议，批量数据变换由代码执行。无法判断的 03/04/2026、逗号小数/千分位、缺失币种进入待确认；用户可选“暂不解决，单列 pending”。并非必须所有问题都解决才可购买，但付款前须明确预计可导入/待确认/移出数量。

P1：模板库、批量文件和工作流连接器；仍保留逐文件合同与追溯。P2：库存/账单等新增领域、更多编码、多工作表和大文件；每个领域需独立语义与校验规则，不泛化宣称可修复任意 Excel。

## 核心指标与需求验证

北极星指标：独立买家完成真实目标导入的任务数。记录诊断→规则确认→报价→有效付费→交付→导入反馈的漏斗；区分用户自行确认的成功与已验证连接器的成功。

质量目标：支持的标准答案样例 100% 符合预期、每条源记录恰有一个去向、未解析值不被猜填、金额精度与币种分组一致。性能目标为固定主机下 30 个上限规格文件的纯规则处理 p95 ≤10 秒，不含模型、支付和网络；总交付处置上限为可履约后 2 分钟，未达到先缩小规格或降低对外承诺。

测试价为 190 分 CNY/限定规格任务。访谈 10–15 位最近有导入失败的用户，收集 5 类获准脱敏表和目标模板；验证是否减少人工时间、是否真能导入、是否愿意购买。内部决策线可用 3 个独立真实购买者、2 个完成目标导入，不能据此估算赛事得分。

## 支付依赖与首版门槛

Machine Pay 的 402 协议由官方 SDK 适配，网页按钮并不等于完成 Machine Pay 集成。先确认异步交付、验付与结算顺序；若只适合同步，缩小服务规格完成同步处理，实际返回已完成结果。规则正确性、幂等、权限隔离、退款与真实目标导入均通过后才开放收费。参见 [D02](../../../../需求文档/00-共用规范/03-资料依据与待确认事项.md)。

# 表格修复站：架构、数据与接口

> 历史基线v1.0：2026-10-27已由“多源资料按规范表自动成表”的v2.0替代，仅作历史记录。当前需求见 [PRD](../../01-产品需求PRD.md)。

P07｜v1.0｜自有 API 设计稿。Machine Pay 的 402 头、凭证、签名和 SDK 方法以实际接入为准，本文不臆造协议。

## 处理管线

```mermaid
flowchart LR
    A[网页或Agent] --> B[上传与安全预检]
    B --> C[诊断与映射建议]
    C --> D[确认规则与报价]
    D --> E[Machine Pay适配]
    E --> F[确定性规则引擎]
    F --> G[分类与守恒校验]
    G --> H[安全导出和变更报告]
    H --> I[权益校验与领取]
```

业务服务采用原生 Python，文件解析器不执行公式/宏，XLSX 解压有文件数、解压体积和时间上限。原始文件先放隔离区；只把已通过预检的值表规范为中间表示。SQL 存订单、配置、任务和摘要，含原值的解析记录与审计文件按内容保存期清理。运行目录为 `E:\dev\sandbox\支付宝黑客松\表格修复站\runtime`。

AI 映射器与规则引擎分离：前者只输出建议，后者只接受确认后的结构化配置。规则函数无模型调用、无任意代码执行，版本锁定；字符/日期/金额转换均有原因码。写输出前先建立每条源记录唯一去向，导出后再独立读回验证类型/行数/数值。

## 数据模型

| 实体 | 主要字段 | 约束 |
| --- | --- | --- |
| Upload | tenant_id、sha256、mime、bytes、state、expires_at | 检查失败不可报价；文件名只作显示 |
| SourceSchema | upload_id、sheet、header_row、columns[{column_id,name,index}]、blank_rows、record_count | 同名列有不同 column_id；原坐标稳定 |
| TargetSchemaVersion | tenant_id、schema_id、version、fields、required、precision、import_notes | 已用版本不可覆盖 |
| Diagnostic | upload_id、schema_version、issue_counts、masked_samples、engine_version | 只保留必要样本；内容到期清理 |
| MappingVersion/RuleSetVersion | column_map、date_policy、number_policy、currency_policy、duplicate_key、pending_policy、confirmed_by/at、hash | 必需歧义没有配置则不得执行为确定值 |
| SourceRecord | record_id、sheet、logical_index、physical_row/span、typed_values | 每个非空记录唯一；CSV 多行单元格保留物理行跨度 |
| Disposition | job_id、record_id、category、issue_codes | 唯一约束 job_id＋record_id；category 三选一 |
| Change | job_id、record_id、column_id、before/after、types、rule_id/version、reason | 包括导出安全转义，正文按结果清理 |
| Quote/Order/Payment/Refund | source/config_hash、amount_fen、policy_version、channel_ref、state | 继承共用支付不变量 |
| Job/Attempt | tenant_id、source_hash、schema/mapping/rule/engine_version、state、attempt、contract_hash | 一个合同一个幂等任务，可有多次尝试 |
| Artifact/Validation | kind、object_key、sha256、row_counts、group_sums、unparsed_counts、expires_at | 完整包校验成功后才授予领取权益 |

金额规范值用十进制字符串，例如 `"1280.00"`，币种独立字段；不能将金额序列化为不受控二进制浮点。规范文本 ID 保留 Unicode/前导零；是否 trim 或大小写变换由规则明确决定。report 的金额总计按币种＋单位＋业务字段＋去向分组，列明解析覆盖数，不把 pending 的未知金额当 0。

## 自有接口

基路径 `/v1/p07`。认证、错误格式、幂等与 cursor 列表沿用共用规范。Agent 可事先完成模板/规则确认，也可在 NEEDS_CONFIRMATION 响应后交给授权用户确认；不得将付款授权等同于用户同意未知数据变换。

| 方法与路径 | 输入 | 返回与状态 |
| --- | --- | --- |
| POST /uploads | multipart file | 201 upload_id、检查状态；413 超限，415 不支持 |
| GET /uploads/{id}/schema | 无 | 工作表/列/记录数/空行摘要，受归属检查 |
| POST /schemas | 字段/类型/必填/精度 | schema_id、version |
| POST /diagnostics | upload_id、sheet、header_row、schema_version | 诊断、建议映射、歧义和 masked_sample 范围 |
| POST /configurations | diagnostic_id、mapping、rules、confirm | immutable config_id、hash、预计三类行数；422 未确认 |
| POST /quotes | upload_id、config_id | quote_id、190、CNY、合同摘要、expires_at |
| POST /jobs | quote_id、config_hash；Idempotency-Key | 未支付按 SDK 返回真实 402 要求；可执行后返回 job_id 与状态，异步模式需 D02 已验证 |
| GET /jobs/{id} | 无 | state、payment_state、quality_status、三类计数、错误和过期时间 |
| POST /jobs/{id}/cancel | reason | 取消、退款/释放授权状态，不能伪称已到账 |
| GET /jobs/{id}/results | 无 | 已结算且具权益时返回 report 摘要、文件清单 |
| POST /artifacts/{id}/download-link | 无 | 5 分钟链接；不重新收费 |
| POST /jobs/{id}/tickets | type、description | 纠错/退款工单 |
| POST /api-keys | scope、expires_at | 管理员专用，明文只返回一次 |
| DELETE /api-keys/{id} | 无 | 撤销，保存审计 |

请求体的 quote/config 不能改变已登记的源内容；同幂等键不同摘要返回 409。402 响应的正文和头部不使用本文业务结构替代，严格由官方适配器生成。已成功任务按原幂等键重复提交返回原结果引用，不再走新收费；查询和下载独立免费。

自有业务结果示例：

```json
{
  "job_id": "job_example",
  "state": "SUCCEEDED",
  "payment_state": "SUCCEEDED",
  "quality_status": "PARTIAL_IMPORTABLE",
  "counts": {"input": 100, "importable": 80, "pending": 18, "excluded": 2},
  "contract_hash": "sha256:example",
  "rule_engine_version": "orders-v1",
  "validation": {"row_conservation": true, "unknown_amount_rows": 4},
  "artifacts": [{"kind": "bundle", "artifact_id": "art_example"}]
}
```

`PARTIAL_IMPORTABLE` 表示约定问题被正确单列，任务本身可成功；若守恒失败、审计缺失或输出坏包则为系统失败。标准错误包括 EMPTY_TABLE、UNSUPPORTED_FORMULA、ENCODING_UNSUPPORTED、NEEDS_CONFIRMATION、SOURCE_DATA_LOSS、QUOTE_EXPIRED、PAYMENT_UNKNOWN、CONTRACT_MISMATCH、VALIDATION_FAILED、ARTIFACT_EXPIRED。EMPTY_TABLE 在报价前返回，不产生支付单。

## 事务与故障恢复

付费执行请求先建立幂等 intent，再调用支付适配器；凭证被确认后以事务保存执行许可与任务/发件箱，不能因为返回 402 或支付超时就把同一 intent 当新单。若官方要求执行后结算，保存任务产物但在结算确认前不公开正式权益；结算失败按原交易恢复，平台计算成本独立计入。

每次处理写临时结果；校验成功后一次性发布完整清单。工作进程崩溃按原配置重跑，不改变模型建议或输入。原表已按政策删除后不承诺可再次计算，仍可在结果有效期领取；如需新的处理，用户重新上传并确认报价。

同步降级必须真的在请求内完成受限处理，并按官方支持方式交付；不可用假成功加轮询偷换不被支持的协议。如果上限规格不能在官方支付超时内稳定完成，降低规格并改新 SKU 合同后再销售。

# 数据库设计与迁移

P07-DEV 2.0.0｜业务 v3.1｜目标 PostgreSQL 18；参考结构未在数据库执行。


## Codex 会话持久化扩展

本版目录共 **62 个参考表**：既有 56 个业务表继续持有账户、任务、合同、规范、来源/记录投影、订单和发布事实；新增 `agent_workspaces`、`agent_sessions`、`agent_turns`、`agent_events`、`agent_checkpoints`、`agent_tool_invocations` 六个内部表。它们不是新增消费者 API 或收费对象。

workspace/session 绑定 task/operation，可空 run 仅用于预检；正式执行绑定 Run。业务 Run 与 Codex thread/turn 不一一混用，thread ID 仅服务端决定。记录 scope/contract/binding hash、SDK/CLI/model/instructions/toolkit、权限版本与 fence/epoch；事件序号幂等，工具调用记录参数摘要/输出/用量，正文只用受控引用。session/workspace/turn 的 owner/task/run 一致性还需应用事务及正式迁移 guards，复合 owner 外键不能替代全部跨实体检查。

暂停采用保存完整 proposal/checkpoint 并释放 compute/lease；修订新 Run/workspace/thread。原 `stage_attempts`/`current_stage` 只用于 Agent invocation/可信验收/发布的运行观测，不再要求每个解析或语义动作有固定阶段任务。来源/字段/行表投影由 Agent 输出账本经验证导入，API 继续分页读取，不把 DB 当 Agent 私有可写工具。

六表中的会话、工具输出、脚本和 checkpoint 都可能含原文，归为内容数据，删除/到期与恢复 tombstone 同步处理；不能按普通无正文审计无限留存。SQL 仍是未执行参考，不包含已经实证的 RLS/GRANT/不可变触发器。


## 数据模型与边界

[完整目录](../../assets/development/v2.0.0/database-catalog.json)和[参考 DDL](../../assets/development/v2.0.0/schema-reference.sql)是同一模型的两种表示。DDL 提供字段、CHECK、唯一约束、复合归属外键和主要索引；应用 service 还必须实现版本、许可、不可变、额度及状态 guard。不能用“有 JSONB”代替领域 schema 校验。

该目录覆盖P0持久化；P1绑定挑战、协作项目和开发者结算的独立物理模型尚未实现，在P1立项时新增迁移/权限/测试。API38/40—43列出的是接口接缝，不代表已有对应P1数据服务。

| 域 | 主要实体 | 不变量 |
| --- | --- | --- |
| 身份/会话 | accounts、platform_identities、sessions | provider + app_alias + subject 唯一；两端默认独立账户 |
| 接收/范围 | tasks、source_files、upload_sessions、task_source_links、source_sets、source_set_items、preflights | 源与规范角色不同；冻结范围只新增版本 |
| 合同/交易 | processing_contracts、quotes、orders、payment_attempts、platform_events、payment_ledger、refunds、entitlement_grants | 报价/合同不可变；原单位、原渠道、未知不重发 |
| 执行/解析 | runs、run_budget_events、stage_attempts、parse_manifests、source_units | 终态 Run 不重开；每 Attempt/源版本可追 |
| 规范 | schema_proposals、schema_bindings | FULL 才采用；不可变绑定具体来源/用途/规范 |
| 结果/依据 | result_versions、records、field_values、evidence、field_evidence、record_lineage、coverage_entries、issues | 记录/字段/证据有稳定 ID；每结果不可变 |
| 人工修订 | decision_previews、decision_batches、decisions、operations、revision_reservations | 一批次至多一个活动操作/预留，成功发布才消费 |
| 交付 | artifact_sets、artifacts、download_grants、export_attempts | 9 文件同一组；设备观察不改付款事实 |
| 隐私/复用 | private_templates、private_template_versions、privacy_policies、consents、deletion_requests、tombstones | 私有规范去事实；撤权先于异步物理清理 |
| 内部/可靠性 | support_tickets、support_access_grants、capability_releases、idempotency_records、jobs、outbox_events、audit_events、reconciliation_runs | 内部角色最小授权；job/outbox 与业务同事务 |

## 通用字段与约束

用户资源统一 `id UUID`、`owner_id UUID`、`created_at timestamptz`；需要乐观锁的可变聚合有 `version bigint >= 1`。历史版本用专用版本号/内容 hash，不原地改 JSONB。引用用户资源用 `(owner_id, referenced_id)` 复合外键，阻止把甲的 source/binding/record 挂给乙。所有主键仍不构成访问许可。

`content_sha256` 为小写 64 hex；JSON 按明确 canonical JSON 规范（键排序、UTF-8、无浮点金额）后计算 hash，并记录 canonicalization_version。原文件 hash 对原字节计算，不能与规范化文本 hash 混用。内容对象 key 由服务生成，不能是用户传入相对/绝对路径。

业务金额使用 `amount_minor bigint >= 0` + `amount_unit` + `provider` + `sku_id`，不把 `CNY_CENT` 与平台代币混算。事实 DECIMAL 用十进制字符串，数值运算用 Python Decimal / 明确精确十进制库；IDENTIFIER 一律 TEXT。容量字节 bigint，计量纳秒/毫秒明确单位，不用浮点累计 900 秒预算。

JSONB 用于规范、受限规则 AST、提案依据、字段 typed value、已脱敏事件摘要等版本化结构。必须先经对应 JSON Schema/领域检查；大正文、原图、OCR 大响应进 objects，表内只留受控引用/摘要。DDL 不存账户/支付明文密钥。

## 关键索引与唯一性

- tasks 按 owner_id / updated_at / id 倒序分页；orders、templates 同理，游标含过滤 hash 和版本。
- source_sets `(owner_id, task_id, version)`；source_set_items 唯一 `(source_set_id, source_id, role)`；不要以全局文件 hash 合并不同账户。
- runs 初始执行以 `(owner_id, contract_id)` 的 root 唯一索引防重复启动；子执行以 decision_batch / active operation 约束防双扣。一个 task 同时最多一个活动 root/child Run，由 task 锁和部分唯一索引共同约束。
- result_versions `(owner_id, task_id, version)`；records `(result_id, stable_key)`；field_values `(record_id, field_id)`；issue 关联同结果，不能跨版本挂靠。
- payment_attempts 的 provider_order_ref、platform_events 的 provider_event_key、ledger 的 provider_fact_key 唯一；退款每次尝试有稳定 merchant_refund_ref 与 retry_of。
- orders 的 `(owner_id,contract_id)` 始终唯一，失败/关闭后如需重新收银创建用户明确确认的新合同版本；不能用按付款状态的部分唯一索引阻断真实晚付款入账。processing_contracts 按task/version唯一，hash包含合同ID/version与快照。
- jobs 按 `status='READY'` 的 available_at / priority / id 建领取索引；outbox 的未发送索引、lease_until 的过期索引；清理和 tombstone 不能只靠全表扫描。
- idempotency_records `(owner_id, route_id, key_hash)`；规范模板名不是唯一业务键，允许同名但版本/ID 区分。

## 必须实现的事务

| 事务 | 锁及前置 | 同一提交内写入 |
| --- | --- | --- |
| 范围确认 | task FOR UPDATE；source_set/goal/规范版本/政策一致 | 不可变 contract、确认事件、task version |
| 建单 | contract + quote；仍有效且无原未决订单 | order + payment attempt + outbox；只为同一原单查回 |
| 验付 | order FOR UPDATE；验签已在事务前通过 | 事件去重、ledger、payment轴、grant、履约 outbox |
| 启动 | task/contract/grant；许可、无删除、预算 | root Run、job、grant 绑定、task 当前指针 |
| 采用 | run/task；FULL/source_set/goal/proposal 精确匹配 | immutable binding、schema 轴、WAITING_SCHEMA→QUEUED、job |
| 提交决定 | task/parent result/reservation；预览 hash 未过期 | batch、decisions、1 round reserve、operation、child Run、job |
| 发布 | task/run/lease/fence；未取消/删除、验收/9文件回读 | result/current pointer、artifact READY、Run成功、round消费、outbox |
| 永久失败 | 当前租约；确定不可恢复 | Run/operation失败、预留释放、原合同售后/退款待办 |
| 删除登记 | owner + 作用域资源锁 | tombstone、download revoke、deletion request、清理 job |

事务隔离默认 READ COMMITTED + 显式行锁 + 条件 UPDATE；对预算、额度和状态不得先读后无条件写。复杂唯一竞争捕获数据库错误并返回原资源/409；死锁和 serialization failure 只重试纯数据库短事务，不能重放已发支付/退款/模型调用。

锁顺序统一：account → task → contract/order → run → operation/reservation → result/artifact；反向模块不得临时换顺序。网络、OCR、模型、文件大读写不放长事务。原生文件写入与 DB 不可能天然两阶段提交，使用不可见 staging + 短事务发布指针 + orphan 回收。

## RLS 与权限

应用查询必须显式 owner predicate、复合外键校归属；RLS 为第二层。正式迁移设置用户表 ENABLE/FORCE ROW LEVEL SECURITY，事务开始通过 `set_config('p07.owner_id', verified_owner, true)` 设置本事务上下文；缺上下文拒绝。连接池复用不依赖 session 级未清理值，禁止客户端提供 owner_id。

migration_owner 不给 API；p07_app 不是表 owner、无 BYPASSRLS/超级用户/DDL；worker 领取全局 jobs 后，用任务 owner 开短事务处理用户数据。跨 owner 队列/补偿由专用最小权限函数或专用内部 role 执行，并记录 resource/owner/reason；不能给整个 API worker 超级用户。参考 DDL 未包含生产 GRANT/完整 RLS，必须在正式迁移和授权试验补齐。

PostgreSQL 表 owner/超级用户/带 BYPASSRLS 的角色可能绕过行安全；TRUNCATE 等也不是 RLS 覆盖范围。不可把“开了 RLS”写作隔离已完成。[官方行安全说明](https://www.postgresql.org/docs/18/ddl-rowsecurity.html)。

## 迁移、删除与恢复

迁移采用 `0001_core.up.sql` 等严格编号；已执行文件不修改，校验摘要登记。每次变更先 expand（新表/可空列/兼容读写）→ 数据回填/验证 → 切换 → 后续 contract；不能一次删旧字段并回退旧 API。schema_reference.sql 为首版参考，非重复可执行 migration。

新库、上一版升级、失败回滚、重复执行检测、角色隔离和并发迁移锁都要真实 PostgreSQL 验证。生产迁移只通过 migration role；先备份并演练，长索引/表锁需评估窗口。破坏性迁移不伪造自动 down，明确从备份恢复与数据影响。

正文删除按 retention category 擦除/失效对象及表内摘录，不把必要支付事实混入删除；财务/审计只保留必要元数据。tombstone 与 deletion-ledger 独立备份，恢复业务库后重放到最新，再开放用户查询/下载。孤儿对象、过期上传和 staging 包分别按引用扫描回收，扫描不能误删仍被已售合同引用的文件。

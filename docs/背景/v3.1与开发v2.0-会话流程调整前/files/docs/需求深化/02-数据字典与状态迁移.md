# 数据字典与状态迁移

P07｜v3.1｜2026-10-27｜自有领域合同，未实现。[结构化状态/预算](../../assets/contracts/domain-contract.v3.1.json)为本页机器索引。

## 统一类型与所有权

ID为不可猜的不透明字符串但不替代授权；所有资源持owner/tenant和创建者，服务端会话决定归属。时间UTC ISO8601，界面本地化。version为正整数、hash为SHA-256；精确数值用规范十进制字符串，支付金额/单位数量用整数；未知为null+原因，不用0/空串。用户文本保留原文另有规范化值，不默默覆盖。

| 实体 | 必需字段与约束 | 生命周期 |
| --- | --- | --- |
| PlatformIdentity | provider/app_id/subject唯一、account_id、verified_at；不依昵称/电话 | 可撤销会话，必要账务独立 |
| Task/Workspace | task_id、owner、origin_channel、mode、goal_version、current_run/result、version | 容器可有多版结果，不等同一笔订单 |
| SourceAsset | source_id、role、name、mime_detected、bytes、sha256、status、expires_at | 原件只读；同角色重试幂等 |
| SourceSetVersion | source_ids/hash/roles、confirmed_exclusions、scope_hash、计量版本 | 冻结后不可覆盖，变动新版本 |
| SourceUnit | unit_id、source_id、page/sheet/cell/paragraph/bbox/span、text_hash、coverage_status | 各单元有去向，不可读有原因 |
| GoalVersion | purpose可空、row_kind候选/明确值、mode、requested_constraints | 关键变动产生新版本 |
| FieldDefinition | field_id、label/order、type、required/nullable、description、unit/scale、constraints | field_id稳定，改标签不改字段身份 |
| SchemaProposal | proposal_version、scope/source_set/goal、PARTIAL/FULL、fields、coverage、unmapped | 全范围才可采用，调整新版本 |
| FieldSuggestion | definition、reason、evidence_ids、observed/relevant_count、sample_scope | 频次/建议不是已批准约束 |
| SchemaVersion/Binding | schema_id/version/hash、origin、fields/row_kind/keys；binding含adopter/source/proposal/goal | 采用事件不可变，旧任务不回写 |
| PrivateTemplateVersion | template_id/version、owner、sanitized_schema、policy_version、deleted_at | 与原源独立，删除撤销新用权限 |
| CandidateRecord | record_id、row_kind、key_candidates、disposition、field_values、relation_ids | 三去向之一，同粒度稳定ID |
| FieldValue | raw、value、type、status、evidence_ids、transform_chain、rule_version | derived/default/user分别标记 |
| Evidence | evidence_id、unit/coordinates、excerpt/hash、relation、expires_at | 摘录和原件可不同到期；不能访问他任务 |
| Issue/Decision | issue/record/field、code/severity/candidates；action/actor/note/expected_result_version | 决定追加，不覆盖旧依据 |
| ExecutionRun/Stage | run/parent_run、stage/attempt/lease/checkpoint、budget_used、status | Run终态不可逆，修订建子Run |
| ResultVersion | result_version、parent_version、run_id、binding、counts、quality、artifact_set | 原子发布，不在旧版上改字段 |
| Contract/Quote | source/goal/schema合同hash、acceptance_policy、policy_version、price/unit、expires | 价格前端不可决定，过期须重报 |
| Order/Payment | origin provider/app/merchant/SKU、quote_hash、platform流水、整数金额/单位 | 由正式验签/查单推进，未知不定失败 |
| Refund | refund_id、order、amount/unit、reason、状态、provider_ref | 独立幂等，累计不超可退实付 |
| Artifact/ExportAttempt | name/type/bytes/hash/version/expires；observed_action/receipt_source | READY与设备取用不同，过期撤链 |
| Operation | operation_id、tenant/action/key/request_hash、resource_id、PENDING/SUCCEEDED/FAILED | 提交未知可查原动作，至少保留任务有效期 |
| CapabilityEvidence | env/app/SKU/build/host/SDK、document/device/approval、date/limits | 文档与准入/真机/审核分别记 |
| Audit/Outbox/DeletionJob | actor/action/resource/version、event_id/retries、tombstone | 最少正文，事务副作用可恢复 |

## 状态轴与界面投影

- 一次执行 `execution`：QUEUED / RUNNING / WAITING_SCHEMA / SUCCEEDED / FAILED / CANCELED。

- 规范 `schema`：NOT_REQUIRED_YET / PARTIAL_DRAFT / FULL_DRAFT / ADOPTED / SUPERSEDED。

- 内容质量 `quality`：NOT_EVALUATED / PASSED / NEEDS_REVIEW / BLOCKED。

- 服务端产物 `artifact`：NOT_READY / BUILDING / READY / FAILED / EXPIRED / REVOKED。

- 付款 `payment`：NOT_REQUIRED / NOT_CREATED / PENDING / CONFIRMED / FAILED / CLOSED / UNKNOWN。

- 退款 `refund`：NONE / REQUESTED / PROCESSING / SUCCEEDED / FAILED / UNKNOWN。

- 履约 `fulfillment`：NOT_STARTED / IN_PROGRESS / DELIVERABLE / DELIVERED / FAILED / CANCELED。

- 异步写动作 `operation`：PENDING / SUCCEEDED / FAILED。

- 设备取用观察 `export_observation`：ARTIFACT_READY / FETCHED / CACHED / OPEN_REQUESTED / OPENED / EXPORT_REQUESTED / USER_CONFIRMED / PLATFORM_CONFIRMED / FAILED / UNKNOWN。

以上为自有映射，不冒充平台官方原始状态；同时保存provider_raw_status及证据，映射版本可追踪。UNKNOWN表示尚未核实，不是失败终态。设备观察为多次事件日志，不强制单调递增：预览成功后导出仍可能失败。

| 用户看到 | 真实组合示例 | 主要动作 |
| --- | --- | --- |
| 等待付款核对 | payment=UNKNOWN/PENDING；run未放行 | 查原单，不再次支付 |
| 待采用规范 | run=WAITING_SCHEMA、schema=FULL_DRAFT、quality=NOT_EVALUATED | 采用/调整准确提案 |
| 可审阅，仍有问题 | run=SUCCEEDED、artifact=READY、quality=NEEDS_REVIEW | 处理问题，不能写全部通过 |
| 全部满足当前规则 | schema=ADOPTED、quality=PASSED、artifact=READY | 领取；仍不推定设备已保存 |
| 已获取未导出 | artifact=READY、export=FETCHED/CACHED | 按宿主路径继续取用 |
| 退款处理中 | refund=REQUESTED/PROCESSING，payment可仍CONFIRMED | 查退款，不写到账 |
| 来源已到期 | SourceAsset=EXPIRED，结果/摘录或仍有效 | 可看仍有效摘录，说明原件不可取 |

## Run允许迁移

| 从 | 到 | 守卫/事件 |
| --- | --- | --- |
| QUEUED | RUNNING | 有效许可、预算、范围、worker租约成立 |
| QUEUED | CANCELED | 取消条件更新成功 |
| QUEUED | FAILED | 启动前预算/依赖不可恢复失败 |
| RUNNING | WAITING_SCHEMA | DISCOVER全范围提案和可审阅预览已持久 |
| WAITING_SCHEMA | QUEUED | 有效全范围提案采用成功后排队继续 |
| WAITING_SCHEMA | CANCELED | 合同允许取消/未采用到期，停止新增计算 |
| WAITING_SCHEMA | FAILED | 已无法履行且确定失败 |
| RUNNING | SUCCEEDED | 当前结果和9文件完整校验后原子发布 |
| RUNNING | FAILED | 预算或依赖/质量结构导致执行不能完成 |
| RUNNING | CANCELED | 取消与发布条件竞争由取消获胜 |

不允许SUCCEEDED→RUNNING；用户修订创建新的子Run，当前Workspace指向进行中修订，同时旧版仍可看。取消与结果发布用task/run版本与租约做条件更新，仅一个分支成功，落后worker输出进隔离清理不能替换当前结果。失败阶段重试是同Run的新Attempt，不重开订单。

规范采用的事务：校owner/全范围/源与目标及提案版本→写Binding/审计→更新schema与run恢复事件→提交发件箱。重复同请求返回原绑定，同键不同载荷409。决定提交同理：锁当前结果→校作用域/输入→存DecisionBatch/Operation→预留一轮→创建子Run；失败恢复原Operation，不二次扣轮次。只有成功发布修订结果才消耗该用户轮次，永久失败释放预留；平台纠错不占余额。

## 时钟与窗口

计算时钟为当前合同下解析/OCR/结构发现/提取/校验/产物与重试/修订实际计算累计，候选上限900秒；排队、人类采用/审阅和通道等待不计计算，但有独立排队/依赖超时告警。900秒不是墙钟必达保证。预算读写在worker租约下原子扣量，不让并发重试超额。

workspace_ready_at首次就绪只记一次：PROVIDED为首版结果，DISCOVER为全范围提案+预览可审阅。候选review_expires_at=ready+24小时，仅在适用SKU允许时采用；平台故障阻断可用审阅时间须记录并恢复合理窗口，不用故障耗尽用户权利。后续修订不任意重新开启无限窗口。

未采用到约定窗口终点：停新增计算，记录未采用原因，STRICT不可标交付完成，按原合同/平台处理退款；BEST_EFFORT也不把未采用草案当正式9文件结果。用户主动到期后再启需显示可行性/新范围，不偷偷续扣。在线内容TTL与售后/账务独立，详见[交易政策](../04-计费交易与运营.md)。

## 不变量与并发

1. 任何ResultVersion必须指向当时不可变Binding及源集；历史结果不能改到新规范。
2. 候选数=ACCEPTED+NEEDS_REVIEW+EXCLUDED；问题数不是记录数，一行可有多问题。
3. 规范required缺失/关键冲突不能ACCEPTED；optional缺失可允许但MISSING状态仍保留。
4. 文件集READY要求9项齐全校验；manifest不自含hash，自身hash由接口返回。
5. payment=CONFIRMED来自有效通道事实，NOT_REQUIRED来自明确免费许可；退款成功不抹除付款历史。
6. refund累计≤原通道可退实付；履约/设备导出观察不自动触发或替代通道结算。
7. 游标绑定result_version/filter/sort/owner；版本变更返回409或重置提示，不能拼两个结果版本分页。
8. 删除/到期/撤权优先于签链续签；短链可能在TTL内已发出，要求边缘校验或撤销机制并说明最坏暴露窗口。

字段/状态增加要同步API样例、状态表、UI投影、追踪与验收，不能只改一个JSON枚举。

## 其他状态轴的允许迁移与守卫

下表与结构化合同同步。表中的规范/质量新版本是工作区投影，旧Binding/Result结论保留。付款CONFIRMED历史不因退款而删除；免费许可不能原地伪转实付。未列迁移需显式业务变更，不能通用“设置状态”接口任意修改。

### schema

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NOT_REQUIRED_YET | PARTIAL_DRAFT | 预检有限分析产出，仅草案，不授权采用 |
| NOT_REQUIRED_YET | FULL_DRAFT | 已确认全范围分析结束并说明未读/排除 |
| PARTIAL_DRAFT | FULL_DRAFT | 创建新的全范围提案版本，保留旧局部版本 |
| FULL_DRAFT | ADOPTED | 用户采用当前源/用途/提案版本的事务成功 |
| ADOPTED | SUPERSEDED | 仅当前工作区新规范已采用的投影；旧Binding及历史结果仍指原规范 |

### quality

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NOT_EVALUATED | PASSED | 有效Binding、结果及规则/证据/重要信息校验均满足 |
| NOT_EVALUATED | NEEDS_REVIEW | 有有效结构和可处理缺项/冲突 |
| NOT_EVALUATED | BLOCKED | 缺有效绑定或严重范围/结构/事实问题 |
| NEEDS_REVIEW | PASSED | 新结果版本复验满足，旧结果质量不覆盖 |
| PASSED | NEEDS_REVIEW | 仅新结果版本因新决定/规范/纠错复验；旧版结论保留 |
| BLOCKED | NEEDS_REVIEW | 新结果版本修复阻断但尚有待核 |

### artifact

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NOT_READY | BUILDING | 已绑定规范和可发布结果，取得当前执行租约 |
| BUILDING | READY | 9文件回读/哈希/版本一致且取消删除守卫未触发，原子发布 |
| BUILDING | FAILED | 任一文件生成/检查失败，隔离半套内容 |
| FAILED | BUILDING | 同Run获准阶段新Attempt，原半包未公开 |
| READY | EXPIRED | 明确内容期限到达，停止签链 |
| READY | REVOKED | 删除/撤权/原合同退款策略触发 |
| BUILDING | REVOKED | 删除或取消先胜，旧worker不得公开 |

### payment

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NOT_CREATED | PENDING | 正式原渠道订单创建及用户主动收银 |
| NOT_CREATED | NOT_REQUIRED | 服务端签发明确免费许可，不造通道流水 |
| PENDING | CONFIRMED | 服务端验签或正式查单核商户/app/单/金额单位 |
| PENDING | FAILED | 原通道明确失败，非客户端超时 |
| PENDING | CLOSED | 原通道明确关单且无已付事实 |
| PENDING | UNKNOWN | 等待超时尚未取得确定事实 |
| UNKNOWN | CONFIRMED | 查原单获得有效付款事实 |
| UNKNOWN | FAILED | 查原单确定失败 |
| UNKNOWN | CLOSED | 查原单确定关单 |
| CLOSED | CONFIRMED | 仅正式晚到已付事实，记录异常并确定履约或原路退 |
| FAILED | CONFIRMED | 仅通道纠正/晚到可验证付款事实，保留原状态事件，不漏记实付 |

### refund

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NONE | REQUESTED | 有可退原实付及明确退款原因，幂等登记申请 |
| REQUESTED | PROCESSING | 原通道已接收处理 |
| REQUESTED | UNKNOWN | 提交超时，查同一退款单 |
| PROCESSING | SUCCEEDED | 通道确认原单位退款事实，累计不超可退 |
| PROCESSING | FAILED | 通道明确失败，进入售后重处置 |
| PROCESSING | UNKNOWN | 结果暂不可确认，不新发第二笔 |
| UNKNOWN | SUCCEEDED | 同退款单查单确认 |
| UNKNOWN | FAILED | 同退款单查单确定失败 |
| FAILED | REQUESTED | 新退款尝试需原失败已确定、额度重新校验及retry_of，不能重放未知款 |

### fulfillment

| 从 | 到 | 守卫 |
| --- | --- | --- |
| NOT_STARTED | IN_PROGRESS | 原合同已付款/明确免费许可并取得执行 |
| IN_PROGRESS | DELIVERABLE | 符合获准商品交付要求的文件/服务已可取用，仍不等于设备导出 |
| DELIVERABLE | DELIVERED | 按适用平台合同有真实交付/履约证据，不直接用缓存回调 |
| NOT_STARTED | CANCELED | 许可/取消最终事实确定 |
| IN_PROGRESS | CANCELED | 取消竞态获胜且原合同权益/退款同步 |
| IN_PROGRESS | FAILED | 不能履约并确认失败/售后 |
| DELIVERABLE | FAILED | 证实原交付损坏或无法取得，按平台纠错/退款处理并保留事件 |

### operation

| 从 | 到 | 守卫 |
| --- | --- | --- |
| PENDING | SUCCEEDED | 目标事务/子执行最终成功且引用资源持久 |
| PENDING | FAILED | 确认永久失败及轮次预留释放，保存错误 |

Operation永久FAILED保持终态，用户明确获准重试创建带retry_of的新Operation，沿用batch唯一约束及当前父版，不重复消费原轮次。临时阶段重试期间原Operation仍PENDING。设备取用观察不强制单向迁移，预览成功后导出失败仍需如实记录。

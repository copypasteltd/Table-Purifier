# 用户故事、业务规则与范围

P07｜v3.1｜2026-10-27｜需求定义，所有产品场景待执行。关联42功能、126条AC。

## 角色与权限

| 角色 | 可以 | 不能 |
| --- | --- | --- |
| 未登录访客 | 看无真实资料合成演示、公开说明 | 上传真实资料、查他人任务、获得收费权益 |
| 资料所有者 | 本人任务提交/采用/决定/领取/私有规范/数据管理 | 用他人ID越权；改前端金额或状态换权益 |
| 客服 | 默认任务/订单摘要，处理工单 | 默认看正文；改事实冒充用户；随意退到其他渠道 |
| 运营 | 能力/成本/故障/商品配置，最小脱敏汇总 | 用生产内容制作公开样例；把未测开关算发布 |
| 引擎Worker | 在租约及本任务权限内处理批准资料 | 付款/外写/读取其他租户/自行改验收规范 |
| P1协作者/API调用者 | 后续明确角色和scope范围 | 因为知道任务ID就拥有访问权 |

P0每租户一个资料所有者的逻辑空间，不暗含企业管理/多人审批。系统操作记录actor_type=USER/SYSTEM/SUPPORT，客服授权含理由、范围、期限和撤销；模型不是人类批准者。

## 代表性用户旅程

S01公司报名表：经办人上传含“姓名/电话/场次”的标准和文字/照片→确认每次报名一行→自动填表→电话OCR歧义列问题→选择原件依据→复验→领取。手机号文本存储；同人多场次不按电话号码去成一行。

S02供应商报价无模板：只交三份报价→系统提议每条商品报价一行及9字段→保修虽只有白石提供也保留可空→用户采用→青禾28元、云杉26元通过，白石单价待议→用户选择保留待补或自行补价→导出状态分明。不把白石保修12个月填给青禾。

S03资料多主题：联系人名录+采购明细→系统说明两个对象粒度→用户选本次采购主表→联系人未纳入有去向说明。多表不在P0，不把未处理联系人当作已覆盖。

S04中断恢复：收银后杀进程→任务列表查原订单→确认实付后发现既有执行→继续规范采用→提交超时查operation→恢复原决定，不重付/不重复扣次。

S05模板复用：主动另存规则快照→原源到期→新任务引用私有模板版本→修改另建版本→旧任务保持原规范；删除模板不自动删账或旧任务绑定。

## 用户输入与系统主动性的边界

系统自动做：可读性检查、主题/字段/单位候选、同义规范化、稳定键归并、确定性验收、来源索引、常规文件生成。系统需要用户确认：关键行粒度/语义歧义、排除来源、采用推荐规范、影响验收的规则变化、冲突取舍/补事实、预算/价格/数据处理授权。正常字段不逐个批准。

自然语言不是任意指令通道。“加保修期”先成为结构变更预览；“没有价格就填0”“忽略这些来源”若改变事实或范围必须明确说明影响，不能用含糊文本自动放宽严格验收。资料内嵌指令无执行权。

## 范围变更分类

| 类别 | 例子 | 流程与费用 |
| --- | --- | --- |
| 平台纠错 | 漏识别原有保修、错合两人、导出损坏 | 原范围修复，保留原因，不扣用户修订轮次/不重收费 |
| 初次采用前同用途调整 | 字段重命名、增加原资料已有字段 | 先看影响，原合同内，不另收采用费；计算预算仍受限 |
| 用户数据修订 | 补白石价格、选择冲突依据 | 合并提交一轮，新结果版本；重复请求不重扣 |
| 扩大服务范围 | 新文件、从报名改库存、更多规模 | 新源/目标/报价确认，不覆盖原订单合同 |
| 平台合同适配 | 某SKU不允许原时间政策 | 先调整可售合同/相应入口和验收，未适配不开收费 |

新增资料在当前预检草稿阶段可更新源集；付费冻结后P0不做静默增量，在原任务中提示新范围/新任务。P1持续追加不由此提前实现。

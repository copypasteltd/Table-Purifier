# 表格修复站：计费、交易与运营

P07｜v3.1｜2026-10-27｜商品与履约合同需求，当前未销售/未开通。以下价格/窗口/保存期是候选政策，必须按目标平台/SKU获准后启用，不是已完成商业授权或法律评审。

## 商品和范围

一单一个确认资料集、用途/模式、规范过程/版本、预算、内容验收和文件交付。DISCOVER包含全范围规范设计、首次采用及原用途内采用前调整，不隐藏收“解锁模板费”。平台纠错不算用户新增需求；新增源/目的/规模先出影响和新报价，不偷偷增量扣费。

STRICT_STANDARD：约定范围和采用规范下结果通过规则/证据/重要信息校验，否则按合同处理纠正/退款。BEST_EFFORT_REPORT：用户购买前主动选完整结构+已有事实+明确问题；不因源事实缺失当然退款，但漏读、错误、坏报告或无法交付仍是平台责任。两政策与PROVIDED/DISCOVER正交；不能结果差时替用户改尽力模式。

所有政策0候选不收/已收全退，免费许可没有退款现金事实。用户到期未采用不能被当成规范/严格服务已通过。详见[业务规则](需求深化/01-用户故事与业务规则.md)。

## 支付、履约与退款状态

支付NOT_REQUIRED/NOT_CREATED/PENDING/CONFIRMED/FAILED/CLOSED/UNKNOWN；退款NONE/REQUESTED/PROCESSING/SUCCEEDED/FAILED/UNKNOWN；履约NOT_STARTED/IN_PROGRESS/DELIVERABLE/DELIVERED/FAILED/CANCELED。自有映射同时存平台原状态，不把生成文件或客户端回调直接映射平台履约完成/可结算。

服务端建单→对应宿主用户主动收银→验签回调或正式查单→核商户/app/订单/商品/金额单位→事件幂等落账+发件箱→一次放行执行。客户端success只触发查询，超时/取消/退出先查原单。原通道流水唯一约束防跨app/租户/任务重放，查询下载不再收费。

退款用原渠道幂等请求和查单/对账；累计不超可退实付/平台单位，不拿退款申请当到账。正式履约/售后或分账时序由通道适配确认，不自行假定托管/24小时预授权。平台用户从统一售后入口申请也须接收和同步，不仅依赖应用内工单。[通用交易指引](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/open-capacity/business-monetization/guaranteed-payment/general/basicapi)

## 窗口和修订候选政策

首次workspace_ready：PROVIDED首版结果，DISCOVER全范围规范草案+预览。候选24小时从首次可实际审阅开始，含两轮用户合并修订；初次采用和采用前原用途调整不扣数据轮次，平台纠错不扣。故障造成不可审阅需恢复合理可用窗口并审计，不让故障耗尽权益。

决定批次提交时预留一轮，子Run成功发布才消耗；永久失败释放，网络重试查同批次不重扣。改源/用途不借修订无限增量。预算耗尽由平台负责停新增开销，原合同不能完成则按失败/退款，不直接让用户自费为平台重试买单。

窗口到期仍未采用或STRICT未达到条件，按获准合同走退款/继续履约，不能自动写通过；BEST_EFFORT也须有采用规范和真实交付，不以草案充正式包。适用SKU不允许候选时间/次数门槛时先调整合同或关闭收费；所有对外展示读取已启用policy_id。

## 事件处理表

| 事件 | 内容与收费动作 |
| --- | --- |
| 无资料/全不可读 | 不执行收费，提示补充 |
| 部分不可读/多主题/超限 | 先说明未处理范围，用户确认新的排除/主表/范围才推进 |
| 没模板 | 正常DISCOVER，不另加隐藏费 |
| 0候选 | 不造记录，已付全退；可提供诊断不冒充成功履约 |
| 漏读/错合/错误规范/坏产物 | 平台纠错不扣轮次，不能履约原路退 |
| 缺源事实 | 显示待补，按事前STRICT/BEST_EFFORT政策处理，不猜值 |
| 手机导出失败 | 重取/获准路径处理；若实际无法交付不能称已履约 |
| 支付晚到/取消完成并发 | 保留已付事实，唯一最终分支，实际履约或原路退，不双退 |
| 退款未知 | 查原退款单，售后入口可用，不再建重复退款 |
| 结果/原件到期 | 明确类别与仍有效内容；必要订单售后持续，不用过期免责任 |

退款后停止未履约执行/未来签链按原合同执行，历史付款/退款仍可查；已主动下载副本不可回收。跨平台绑定不自动共享付费权益或挪动退款原渠道。

## 留存和成本运营

候选未购买源24小时、工作区源最迟ready后48小时、失败无工作区终态后24小时、各版提案/结果/摘录7天；主动另存的去事实规范至删除/注销。这些是数据清理草案，必须满足实际商品履约与售后后才能启用，不能删源后宣称所有原信息都已消失。账务/日志/备份与正文分离，见[隐私专项](小程序/05-数据隐私与安全.md)。

成本台账按合同包括免费预检、OCR/模型、规范调整、提取/归并/校验、重试/修订、页图和9文件、流量、通道费/退款、客服和双端运维。至少用30组标准集和试点真实成本重估售价，不延用1.9元/2分钟承诺。实收/退款/结算/贡献分别统计。

客服默认最小摘要，正文要限时授权；候选工作日1工作日响应需运营能力确认，不宣称7×24。后台记录未知款/退款、异常费用、清理失败、开关/回退、发布证据。严重内容/资金/隐私错误暂停相关新单，保留原订单查询与售后，修复/退款并复验后恢复。

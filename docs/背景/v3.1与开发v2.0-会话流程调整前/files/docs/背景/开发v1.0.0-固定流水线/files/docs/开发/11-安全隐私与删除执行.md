# 安全、隐私与删除执行

P07-DEV 1.0.0｜业务 v3.1｜W02/W03/W09/W12 实施要求；不是已完成安全评估。

## 威胁与控制

| 边界 | 具体威胁 | 必须控制/证据 |
| --- | --- | --- |
| 手机→API | 猜 ID/换 owner、伪造支付、重复提交 | 服务端会话、资源 owner、版本/幂等、原通道验真 |
| 文件→解析 | ZIP/XML 炸弹、路径逃逸、PDF/图片耗尽、宏/外链 | quarantine、实测资源限额、原生受限子进程、不执行内容 |
| 来源→模型 | 提示注入、冒充系统命令/退款指令、敏感外发 | 无工具权限、受限 schema、数据角色、供应商准入与最少范围 |
| 模型→结果 | 编造、错对象/单位、篡改 schema/质量 | 证据/范围/规则独立验证、人工质量标准集、显式待核 |
| 对象→用户 | 长期公开 URL、短链转发、删除后取用 | 私有 ObjectStore、短 grant、每请求撤权、日志去 query |
| 内部→内容 | 客服无限浏览、误删/强制改款 | 分角色、限时范围授权、业务 service、审计与复核 |
| 备份→恢复 | 旧备份使已删除内容复活 | 独立 tombstone ledger、恢复先重放再开放 |

## 访问矩阵

消费者只读写本人资源及当前合法动作；不能用 app_alias/phone/nickname 推导跨端 owner。工单元数据客服可按权限查看，正文需用户主动 opt-in、指定 task/result、时间上限和 purpose；support_access_grants 到期/撤回立即失效，引用正文的每个访问都审计。

operator 按 release_admin、finance_reconciler、support_agent、privacy_operator、read_only 分权。release_admin 可关能力，不可改商户收款账户/事实值；finance 可查原单/触发获准退款，不看全量正文；隐私清理不默认有支付密钥。高权限动作明确资源和影响，操作记录 actor/reason/request/version，不能用一个全能管理员 token 给手机。

数据库 runtime roles 无 DDL/超级用户，文件 ACL 按服务账户分配；Python 无 DB/支付秘密。生产 HTTPS、严格域名/证书和可信代理配置；不信任任意 X-Forwarded-For。rate limit 以账户/端点/预算为主，IP 仅辅助且考虑共享网络；认证、上传许可、语义预检、下载签链分别限额。

## 秘密和日志

运行秘密在 runtime/secrets/受控注入，不写 assets、docs、源码、截图、命令参数、错误栈、构建产物。日志允许 request_id/task/run/stage/attempt/operation、版本、耗时/字节/计量、错误码；禁止原文/完整身份证号/手机号、OCR原响应、支付签名、token/短链 query、数据库密码。

异常输入也可能把正文带入 validator error，统一脱敏 logger 只记录字段 path、码和长度。敏感过滤测试含嵌套 JSON、URL、header、异常堆栈及导出失败；不能只靠字符串 regex 就宣称零泄露。traces 遵同策略，debug 也不能在生产开启正文日志。

供应商 key 支持新旧短窗口轮换、最小权限和额度限制；真实替换、撤旧和失败恢复演练后留证据。会话/上传/下载 token 只存 hash，访问过期/revoked 资源返回明确状态而不泄露其他内容。

## 处理告知与供应商接入

privacy_policy 固定版本、用途、处理方类别/地域/保留条件、数据期限及删除影响。添加真实资料前取得必要同意；可选改进训练/营销不得默认勾选或混为必需。撤回时停止相关新处理并解释已售履约/必要账务影响，不宣称已有外部副本瞬间消失。

OCR/模型上线前核可签约主体、内容是否用于训练、地域/跨境、保留/日志、删除 API、分包商、故障/费用/限额及安全责任；来源为真实合同/控制台证据，不从营销文案推断“零保留”。供应商不可满足时更换或公开实际限制并评审，不能伪填 PASS。

## 删除状态与步骤

deletion request 内部状态 REQUESTED → ACCESS_REVOKED → PURGING → COMPLETED / PARTIAL_FAILED；这些不是 Run 执行状态。每项清理对象记录 scope、provider、attempt、receipt、remaining_category，重复执行幂等。

1. 校本人和明确 scope（任务内容/私有规范/账户）；显示进行中订单、保留必要账务、用户导出副本和供应商/备份限制。
2. 事务登记 tombstone、bump task epoch、revoke downloads/support grants、阻止新 job/采用/发布，返回 202。界面先显示访问已撤/清理中。
3. 清对象、原件、规范上传、解析/OCR、摘录/证据、提案/结果、临时/缓存/索引；擦除数据库敏感字段，必要财务保留最少元数据。
4. 发供应商删除请求并查实际回执，不支持时按已告知期限追踪；失败进入重试/告警，不能标全部完成。
5. 写独立删除 ledger 并标线上完成范围，备份到期单列；恢复任何备份都先重放该 ledger，再放访问。

候选目标撤权≤1分钟、线上清理≤24小时、备份轮换30天，需环境/合同确认后才承诺。主动另存私有规范独立保留，任务删除不默删它；注销/显式模板删除另按 scope。已下载/在途字节不可远程召回。

## 安全事件与发布阻断

越权、未标记严重编造/错金额/错对象、重复收退、删除后重新开放、泄露秘密任一出现，暂停受影响新处理/收费，保存最少证据与原订单售后。定位 actor/build/版本/范围，轮换必要密钥、撤权、纠错/退款，修复后回归同类反例。不得用删日志或改数据库历史掩盖事件。

静态检查只是前置；真实 HTTP 越权、恶意文件、并发撤权、日志扫描、恢复重放、供应商删除及客服权限测试均是发布条件。

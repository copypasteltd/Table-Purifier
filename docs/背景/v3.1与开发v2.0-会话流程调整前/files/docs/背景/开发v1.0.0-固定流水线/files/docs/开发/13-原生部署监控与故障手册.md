# 原生部署、监控与故障手册

P07-DEV 1.0.0｜业务 v3.1｜Windows 原生部署参考，当前未部署。

## 拓扑与服务管理

开发与首轮内测采用独立 Windows 原生 API、Worker、scheduler、PostgreSQL 服务/进程，私有对象在项目 runtime。生产部署到具备必要网络/证书/磁盘/备份能力的 Windows 机器，同样不依赖 Docker、WSL 或虚拟机。当前本地路径约束保持；正式目标机器/盘符变更需部署清单明确映射，不能悄悄外移客户数据。

HTTPS 终止使用经试验的原生反向代理/系统服务，具体软件/证书自动续期方式在 W12 锁版本；数据库不公网开放，API behind proxy 只信任已知代理，管理端独立ACL。OCR/模型/平台仅出站白名单；不把 runtime/objects 配成静态站点。

服务 wrapper 需要 graceful stop、失败重启限速、独立账户/ACL、日志轮换、项目 TEMP、工作目录和 PID/build/config 指纹。启动后台 helper 用隐藏窗口；停止只处理自己登记且核 exe/path/owner 的 PID，不按名字 kill 所有 node/python。退出时 worker 停新领取、完成短事务/交还 lease，随后终止子进程树。

## 配置与发布清单

release manifest 至少包括 git/build ID、Node/Python/PostgreSQL/依赖精确版本、DB migration checksum、业务/设计/开发基线、模型/OCR/parser/prompt/rule/policy/SDK、四环境 capability、域名、对象适配器和测试证据索引。真实秘密不在 manifest，记录 secret reference/version。

发布步骤：先备份与恢复点→检查准入证据和旧订单兼容→expand迁移→部署 Worker/API/scheduler→ready 与合成 smoke→限定受众免费/受控灰度→核真实文件/资金/费用→逐环境/SKU打开新单。部署/公开发布另按当次授权执行，本文不触发自动上线。

新单开关与原单服务分离。关闭新收费/处理仍应保留查单、退款、工单、已售取用与必要恢复/清理；不能全站封锁导致用户失去售后。规则/模型回退不修改历史结果或已售policy，已有进行中Run继续锁定版本或经审计纠错。

## 健康与监控

`/health/live` 只报进程存活，`/health/ready` 核数据库连接/迁移、对象可用、必要配置；不把供应商瞬时故障导致整个进程无限重启。公开健康输出不暴露内部host/版本/秘密。Worker心跳/queue积压、scheduler lease独立监测。

| 信号 | 候选告警条件 | 处置 |
| --- | --- | --- |
| job backlog / oldest age | 相对试点基线持续超预算 | 暂停新计算、查worker/DB/外部限流，保留已付恢复 |
| lease/fence冲突、阶段失败率 | 短窗突升 | 查版本/资源/依赖，拒绝旧worker写 |
| 计算/模型费用 | 合同预算将尽/成本异常 | 截止后续调用、查重试/注入，按合同处理 |
| 未知付款/退款 | 候选10分钟未决 | 原渠道查同单，运营接手，不再收费/重复退 |
| 9文件/hash失败 | 任一已READY不一致 | 撤受影响取用，纠错/退款，查版本与磁盘 |
| 越权/严重事实错误/重复收退 | 任一确认事件 | 停受影响新单，安全/资金复核 |
| 删除/到期清理失败 | 超已确认目标或连续失败 | 撤权保持，重试/升级，显示实际范围 |
| 备份/磁盘/证书 | 备份失败、容量/有效期低于锁定阈值 | 限新上传、恢复备份/续证，不删未到期业务内容腾空间 |

阈值经 W01/W11 锁定，告警内容仅 IDs/错误码/计量，不能发用户正文或签链。request/task/run/stage/attempt/operation/order关联查问题；不因为追踪方便记录全量敏感输入。

## 备份与恢复演练

数据库备份基于原生 PostgreSQL 工具，候选每小时恢复点/RPO≤1小时、RTO≤4小时须实际测量；只做每日dump不能声称小时RPO。若选择 WAL/PITR，需配archive连续性和恢复链验证，不能只写开关。对象按不可变key与manifest备份，记录数据库时间点/对象清单一致性。

删除ledger/tombstone单独保存最新副本，备份访问受控/加密并按获准期限轮换。备份文件也在 runtime/backups；不把真实备份打进公开ZIP。

恢复步骤：隔离目标→停止访问/新单→校备份hash/版本/恢复点→恢复DB与对象→重放到最新删除/撤权ledger→重建队列/检查未知款→核9文件/hash/owner→合成与真实许可回归→审批后开放。重放前不能让用户下载旧已删内容。演练报告记录真实耗时/丢失窗口/失败，不预填达标。

## 故障操作卡

| 事故 | 立即动作 | 恢复条件 |
| --- | --- | --- |
| Worker全部停止 | 停新计算、查lease/进程/磁盘，确认无活worker后原生重启 | 旧fence失效、积压可恢复、预算不重置 |
| DB不可用 | API拒绝授权写/新收单，禁止本地假确认；保留安全静态说明 | DB恢复/迁移一致、补偿outbox/原通道核对 |
| 供应商超时/费用飙升 | 暂停受影响provider新调用，查询原request/用量 | 明确结果/费用、预算和样本回归通过 |
| 支付/退款不一致 | 停受影响新收费、原单对账 | 资金事实闭合、补偿/退款有真实回执 |
| 成果损坏/严重事实错 | 撤受影响grant、告知工单、保留原版审计 | 新子Run修复/重新验收，按原合同补偿 |
| 删除后可访问 | 立即关相关下载/签链，扩大tombstone检查 | 竞态修复、Range/恢复/缓存回归通过 |
| 新版发布回归 | 关闭新单、停领取新版job、兼容旧API/Worker回滚 | migration兼容、进行中/已售单可服务 |

人工处置调用受控CLI/application service，带resource/reason/operator与dry-run；不能手改CONFIRMED/READY/轮次。CLI尚未实现，任务清单列入W12；真实 runbook 应在首轮演练后补精确命令和证据，不把本表当已验证自动恢复能力。

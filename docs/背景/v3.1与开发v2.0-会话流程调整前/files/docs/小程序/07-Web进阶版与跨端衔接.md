# 表格修复站：Web进阶版与跨端衔接

P07｜v3.1｜2026-10-27｜P1规划，非本轮小程序P0依赖。关联P07-F21、F22、F28、F42。

## Web的目标用户和价值

手机完成资料提交、规范采用、整理、问题处理和领取；大屏面向需要长期核对大量列、对比多个版本、精细配置字段或批量处理的用户。Web沿用两种规范模式和事实/范围/验收合同，不能另造一套“宽松通过”逻辑。

| 能力 | Web进阶设计 | 首版小程序对应能力 |
| --- | --- | --- |
| 大屏工作区 | 资料/页图、结果表、问题解释并排，可调整面板 | 记录卡→详情→来源，逐级返回保持位置 |
| 多列与批改 | 键盘选区、列设置、明确作用域批量规则及预览 | 分组字段/问题卡，有限同语义批量决定 |
| 规范设计 | 字段/类型/规则完整编辑、版本比较、影响范围 | 推荐卡、一键采用、字段编辑和自然语言修改 |
| 任务管理 | 多任务筛选、版本差异、成本/期限管理 | 任务列表与单任务详情 |
| 扩展 | 协作、增量、多表/连接器/更大规模分批验证 | P0仍一个任务一个主要结果表 |

Web的表格编辑也要记录人工来源和版本，不能直接修改导出文件后宣称引擎已复验。多表、协作、更大规模不因有桌面空间自动进入P0合同，分别做权限、成本及质量验收。

## 辅助文件页与进阶版的区别

若平台允许，可有非常有限的文件接力/领取页，供指定任务传文件或取结果。它不含大屏整理、批量改表、复杂管理或收款，不是Web进阶版提前完成，也不能作为普通任务必买的产品。

辅助页必须证明归属、短期单用途和撤销；无获准安全路径就关闭，当前不承诺任意外跳、二维码或扫码方式都允许。小程序导出有缺口时明确受限内测，不以Web规划掩盖。

## 跨端身份和权益

Web登录要有自己的安全会话，可在平台允许范围关联已验证身份；两端分别认证、明示共享范围。不能靠昵称、手机号、openid相似或知道task_id连接用户，不能默认在Web解锁另一个平台购买权益。

任务保留origin_channel、订单/退款原渠道及适用政策。是否能跨端访问收费任务、免费任务或私有模板逐类验证；未允许则只在原端交付，不引导iOS/其他受限宿主去Web付款。用户主动下载文件不等于赋予跨平台服务额度。

## 数据与并发合同

同一个Task/SourceSetVersion/SchemaBinding/ResultVersion、证据和文件manifest供不同获准端展示。修改带expected_version；手机和Web并发时旧请求返回版本冲突及比较入口，不能最后写入覆盖。历史结果和规范不可变。

修改规则、追加资料或扩大预算先生成影响摘要/范围确认，新增收费必须独立报价且符合原渠道要求。平台纠错不算新增需求。Web上的人工补值与手机同等标记，不绕规范校验或归并审核。

## P1实施与验收门槛

开始Web前，小程序普通任务闭环、共享后端、质量/版本/支付/文件安全达到可用基线。若商业验证表明大屏需求优先，可以重新排序，但必须明确变更范围，不能默默改回网页首版。

Web需验证：两模式兼容、资料与单元格证据联动、可访问的大表操作、批改预览/撤销/复验、并发冲突、跨端归属/权益与退款、源/结果到期、文件下载安全和大规模真实成本。协作增加角色/撤权/审计测试，多表增加关系与粒度测试，开放API另核Machine Pay契约。

当前仅保留src/web目录与设计，不提供Web完成日期或已实现承诺。[实施顺序](../实施/小程序优先开发任务与里程碑.md)先验证双小程序，Web另行估算。

## v3.1沿用合同与后续定型

Web沿用B青绿资料夹的色彩/字体/组件语义，分屏密度/键盘选区需单独P1页面定型，不拿手机3张图当Web成稿。复用相同53项领域API中的可适用部分和正交状态、不可变版本、决定预览/提交/原动作查询。

F21协作、F22复杂多表、F28开放API各自仍需独立权限/关系/计费/质量专题；本文只明确边界与接口预留，不声称这些P1已有完整可实施子规格。首版范围保持38项P0，Web不算普通任务的前置依赖。

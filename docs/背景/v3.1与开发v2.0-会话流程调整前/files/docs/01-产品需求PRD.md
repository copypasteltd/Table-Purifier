# 表格修复站：产品需求PRD

P07｜业务基线v3.1｜2026-10-27｜需求深化完成，软件未实现，外部能力与真机验收待执行。视觉基线为用户选定B「青绿资料夹」P07-DS-B 1.0.0。

## 产品定义

用户交来零散文字、图片、文档或现有表格，系统把它们读成有来源、可核对、可继续使用的规范表。已有标准时按标准验收；没有标准时先分析资料、推荐规范，由用户采用后自动整理。产品名保留“表格修复站”，实际服务包含从无表到成表，不限制为修坏Excel。

支付宝、抖音小程序为P0主载体，Web进阶为P1。普通整理在手机完成：添加资料→确认范围与费用→系统处理→必要规范采用/关键问题→领取结果。主交互为文件/文字队列、规范卡、记录卡和问题卡；自然语言用作可选用途与修改指令，不要求长聊天，不让用户手动逐列映射或逐格批准正常事实。

## 用户、目标与成功定义

首版用户为独立经办人、小商家和小团队中的单个整理者，优先报名/联系人与采购/报价两主题。多人协作、长期增量、多表关联不进入首版。用户应有资料处理权限；演示与公开测试只用合成或明确授权内容。

| 任务 | 要解决的问题 | 完成证据 |
| --- | --- | --- |
| 按公司模板填表 | 各来源措辞不同、人工复制易漏 | 目标列/规则保留，结果有值且字段可追溯 |
| 没有表格模板 | 不会决定字段、粒度、类型 | 系统给完整建议及依据，用户采用后得到空规范与已填结果 |
| 多份资料归并 | 同名/多次事件/冲突难辨 | 合并键有依据、拆合可查、冲突保留候选 |
| 手机现场整理 | 宽表难编辑、退出易丢进度 | 手机处理必要问题、重入恢复原动作、真实取得文件 |
| 重复同类工作 | 每次重做规则 | 主动保存去事实的私有规范，可独立复用 |

产品目标为减少阅读、设计表头和搬运时间，并减少漏记录/错字段。效率改善须用相同资料的人工对照和实际试用证明，当前无提升百分比结论。单次成功同时要求来源范围明确、规范已明确/采用、事实有据、问题可处理、合同文件齐全且实际可取得、资金与售后状态正确。执行成功或模型高分不能单独代表业务成功。

## 范围与优先级

P0包括主动图文/获支持文档输入、两模式规范、预检报价、自动抽取清理拆合、规则/证据/覆盖检查、手机问题审阅、9文件、私有规范、原渠道账号订单支付退款、隐私和恢复、能力开关。双平台×两OS分别验收，不以套Web页或一端演示替代。

P1仅F21增量与协作、F22更多格式/复杂规范、F28开放连接器/SDK/Machine Pay、F42 Web进阶。首版不承诺任意格式都能解析、自动读取聊天/网盘、任意URL抓取、公开模板市场、自动外写、自动换汇或专业审计判断。“任意资料”表达用户入口愿景，实际接受类型、大小、平台路径在提交前明示。

## 输入、计量与输出

计划服务端范围：粘贴文本、TXT/Markdown、CSV/XLSX、DOCX正文/表格、文字/扫描PDF、JPG/PNG。密码/损坏文件、宏/嵌入代码不执行；复杂图表、公式计算、手写/低清OCR不能默认承诺准确。来源与规范文件角色分开，模板样例不成为事实。

试点硬上限：10个SOURCE文件、单20,000,000字节、总50,000,000字节；粘贴文本合计50,000 Unicode码点；PDF页/DOCX确定分块/独立图片合计50处理单元；目标50字段、1000候选；模板另限5,000,000字节。文本/表格解析仍受资源预算。详细规则见[引擎规格](需求深化/03-整理引擎与规范验收规格.md)。端侧选择/缓存限制另核，取更小值先告知；超限不截断后声称处理完整。

固定输出9项：standard.xlsx、standard.json、result.xlsx、accepted.csv、result.json、issues.xlsx、provenance.jsonl、validation.json、manifest.json。手机突出结果Excel、空白规范、问题报告，其余可展开领取。主结果含所有未移出候选并配状态附表；accepted.csv仅通过行。空集保留结构；0候选不捏造记录，按合同退费。

## 两模式完整流程

PROVIDED：添加资料→选择私有规范/上传目标模板/手机编辑→明确表头、行粒度、规则与样例区→预检和范围确认→获准交易或免费许可→自动提取与验收→必要问题处理→领取。关键目标歧义在冻结前澄清，付款不视作同意未知规则。

DISCOVER：添加资料及可选用途→预检最多3单元的局部建议→确认发现/整理范围和费用→全范围分析主题/对象/字段→显示完整提案、代表预览与未纳入项→用户采用或调整→追加不可变规范绑定→自动整理/验收→集中处理问题→领取。未采用只能展示草案，不可称正式规范通过；全范围发现仍要说明不可读或明确排除单元。

无模板时优先提出保留事实的默认方案；多主题只在影响主表时问本次目标。低频重要信息不因只有一个来源而丢弃。观察数据不自动证明字段必填、全局唯一或枚举封闭。字段名相同但含义不同不能强合。

## 交互与视觉合同

四个根入口：整理MP01、任务MP13、规范MP14、我的MP15；其余为任务详情页/子流程，总18页。首页只需添加资料；推荐页让用户理解一行和字段；问题页初始无决定，选补值才展开输入，值有效才能提交，“保留待补”仍为待补。来源到期必须讲明不能查看原件，不能生成假证据。

B体系：雾绿页面、白阅读面、青绿主动作、有限资料夹页签、清楚字段索引。原生标题/胶囊/收银/授权按宿主实现。字体、颜色、触控、大字号/键盘及安全区按[设计定型](设计定型/B-青绿资料夹-v1.0.0/README.md)和[v3.1兼容说明](需求深化/06-需求追踪与变更管理.md)执行。现有3页图像锚点不代表18页已画成或已开发。

## 状态、时间与用户决定

任务是容器，执行Run、规范、质量、结果版本、产物、付款、退款、履约、设备取用为独立轴。首版结果SUCCEEDED但NEEDS_REVIEW属于真实可审阅状态；用户修订创建子Run/新结果，旧成功Run不回写RUNNING。未采用DISCOVER暂停WAITING_SCHEMA，不消耗后台计算时长；等待/超时/退款由明确合同处理。

默认不预选问题决定；人工补值有作者/说明；冲突不默认取最近上传；缺事实不补0。任何关键规则变更先预览影响，不能删列/放宽必填制造通过。查询/下载/失败重试不重复收费；旧版本、重复提交、取消与完成竞态可查可恢复。

## 商业与平台可行性

STRICT_STANDARD与BEST_EFFORT_REPORT是购买前选择的内容合同，独立于规范来源模式。严格模式未达约定条件按退款契约处理；尽力报告也不能免除漏读/错误/坏文件交付责任。所有模式0候选全退，免费任务显示免费，不造支付流水。

试点候选24小时审阅/两轮修订/7天在线文件等不直接绑定所有平台：需要确认本SKU适用的履约、时间与交付限制后才能启用。抖音iOS当前官方规则使用平台虚拟支付能力并限制外部引导；本项目仍未获准可售/开通。若候选条款不适配，先建立适配SKU或关闭收费，不靠用户勾选豁免平台规则。具体价格/费率/最低版本待实测锁定。

平台身份按provider/app_id/subject映射，两端不按昵称/手机号自动合并。P0双端可独立用，绑定与跨端收费权益没有验证则关闭。消费者收银、Machine Pay开放API与赛事AI付认可分别核证。[当前官方复核](资料/双小程序官方能力复核-v3.1-2026-10-27.md)为文档证据，不是应用开通证明。

## 隐私、质量与发布

真实上传前告知处理方/地域、OCR/模型用途、期限和删除路径；本平台默认不训练/公开，第三方零留存不作无合同承诺。真实源/中间/结果/证据/数据库/日志在受控runtime，公共assets仅合成设计材料。私有规范去事实、证据、访问引用后另存，字段/规则本身仍私有。源到期不代表摘录同刻消失，在线文件到期不终止售后。

至少30组独立人工标准答案，含不少于10组无模板、两主题、混合来源及异常。发布目标字段准确率≥98%、记录召回≥95%、无模板关键字段覆盖≥95%；关键标识/金额/数量/粒度无未标记严重错误，另测字段输出覆盖防止“全填null”。定义与分母见[质量及非功能规格](需求深化/04-非功能安全与运营需求.md)。当前指标未实测。

四发布单元分别过G01—G10。文件选择、服务端解析、宿主预览、实际导出是不同证据；本轮无正式交易、设备或审核PASS。完整P0前可受限免费演示，范围清楚；无实际Excel交付路径不卖文件服务。估算仍需M0/M1后重估，不以深化文档承诺上线日期。

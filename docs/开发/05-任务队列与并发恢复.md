# 任务队列与并发恢复

P07｜业务v3.2｜开发P07-DEV 3.0.0｜2026-10-27｜设计B青绿资料夹1.0.0。设计资料，软件及真实Agent/资金/设备测试未执行。

S1 创建会话并完整预加载Skill → S2 用户提交信息 → S3 Agent分析 → S4 用户确认或调整 → S5 预估计费 → S6 实付后批量产出 → S7 独立保存结果、释放Agent并销毁任务运行环境。


Job类型是BOOTSTRAP、ANALYZE、ADJUST、PAID_BATCH、PUBLISH、CLEANUP等持久意图，Agent内部读取/工具/脚本循环不拆固定业务流水线。Bootstrap先完整装Skill，成功后开放输入。分析与确认/付款等待属于session，付款前没有生产Run。

同session一个active turn，DB租约/fence/epoch决定写权；用户确认/支付等待不占active compute，idle期限另锁定。分析预算平台承担，与已付900秒批量合同预算分离；重试与获准纠错计原合同，未知外部副作用先查原调用。

进行中崩溃恢复同时核thread映射、文件inventory、Skill/源/plan/binding、付款及剩余预算，旧writer必须先中止/撤权。产出后持久提交result+cleanup outbox，清理器停止进程树/清任务上下文，CLOSED不再恢复。复制/提交结果失败不能当产出成功删唯一材料；已存结果的清理重试不重跑Agent或收费。

## 实施细则

## 租约、预算与提交

PostgreSQL READY/LEASED/DONE/DEAD job 使用 `FOR UPDATE SKIP LOCKED` 领取；租约起点参考 60 秒、心跳 15 秒、空闲 poll 2 秒，需真实压测锁定。心跳/提交按 job + lease_owner + fence 条件更新，DB 时间为准。一个 thread 同时一个 turn，一个合同同时一个 active compute lease。

每次 Agent 会话/turn 写入 owner、task、run/operation、workspace、source/goal/contract/binding hash、SDK/CLI/model/instructions/toolkit/validator 版本及 fence/epoch。发布前再次检查 grant、父版本、取消、删除、当前租约和任务 epoch；旧 worker 迟到输出只能隔离，不能发布或消费轮次。

900 秒为实付后同合同批量生产累计 active compute 上限，包含模型等待、工具执行、受控修复、自动恢复与子 Run。排队、用户查看提案/人工决定的等待不计。计时由宿主可信时钟/预算事件计算，Agent 自述耗时和 token 不是权威账本。token/外部费用另记运营用量，不改变已确认计价单位。

自动失败恢复最多一次且共用剩余预算；这不是把 Agent 正常的读写/调试循环限制成一次。工具副作用默认局限工作区。可能产生费用/外部副作用的操作持久记录 call key/request ID，未知结果先查原动作，不盲重发；工具/供应商不支持查询时按明确风险策略停止，不承诺恰好一次外部扣费。



## 双重检查点

恢复同时依赖 Codex 会话和实际文件。记录 thread ID/turn序号、输入版本、文件 inventory/hash、已完成工具调用、coverage、候选/脚本引用、budget snapshot。只保留聊天历史不能恢复已丢的 XLSX 或脚本；只保留文件也不能假定 thread 可继续。

宿主先封存 staging 文件，再在短事务中登记 checkpoint。文件存在 DB 未提交是 orphan；DB 指向丢失/损坏文件是失败诊断，不假成功。工作区/会话权限与源集任一不一致，拒绝盲恢复。恢复只能用服务端持久化的准确 thread ID，不使用客户端传入 ID 或 `--last`。


### 阶段作业与清理故障

BOOTSTRAP/ANALYZE/ADJUST的限时/调用/轮数/idle参数在真实SDK试验后锁定，默认未配置时不开会话。确认/付款等待保留有限会话数据但不占计算租约。不能把预付分析预算记入之后用户实付费用。

| 故障边界 | 恢复方式 |
| --- | --- |
| 初始化缺Skill/hash/上下文容量 | 初始化失败；不收输入，停止清已分配环境 |
| 分析中断 | 仅同未关闭session恢复，重附完整Skill和准确输入版本 |
| 付款UNKNOWN | 查原单，不新收、不启动批量、不假定未付 |
| 已实付而环境已清 | 不复活旧环境；按原单进入新session/必要重传或原路退款 |
| 复制结果或持久提交失败 | 不标产出成功，不删唯一可恢复候选；有界重试后履约失败处置 |
| 发布提交成功而清理前崩溃 | cleanup outbox可靠重放，无需重新生产或收费 |
| 进程/文件占用导致清理失败 | cleanup FAILED/PENDING重试告警；结果继续授权访问 |

检查点/脚本/原始工具输出与会话正文一起清理；CLOSED仅留无正文墓碑，不再有可恢复检查点。不要以SDK的一次close调用代替进程树/临时文件/受控副本的实际回收。

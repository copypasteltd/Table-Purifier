# 订单支付退款与对账

P07｜业务v3.2｜开发P07-DEV 3.0.0｜2026-10-27｜设计B青绿资料夹1.0.0。设计资料，软件及真实Agent/资金/设备测试未执行。

S1 创建会话并完整预加载Skill → S2 用户提交信息 → S3 Agent分析 → S4 用户确认或调整 → S5 预估计费 → S6 实付后批量产出 → S7 独立保存结果、释放Agent并销毁任务运行环境。


## 收费时机

必须先完成完整会话预载、提交信息、Agent分析和用户确认；随后才预估计费。PROVIDED与DISCOVER一致，无模板完整规范发现不再放到付款之后。初始化/分析/调整费用由平台承担并设独立有限预算，不能把已发生成本事后加到未确认价格。

报价绑定session、confirmed plan ID/version/hash、source/binding/Skill hash、原平台app/OS/SKU、价格表版本、可信计量、原单位金额/上限、有效期及交付/退款政策。LLM只能建议复杂度/工作量，不能决定实收价格；默认按确认范围封顶，超限停止说明，不隐性加费。价目与分析/空闲阈值实测试验锁定前关闭生产。

## 实付与生产

正常消费者生产只接受服务端原渠道验签/正式查单CONFIRMED；客户端success、UNKNOWN、旧quote、金额/单位/计划hash不匹配及free_grant都不能启动。获准平台收银资格、app/类目/SKU/OS能力独立真机证明；未核不借Web/其他平台绕过。不以公开免费生产路径跳过用户要求的实付门槛。

相同合同只有一张原订单。幂等请求/重复/乱序回调追加正确资金事实，只产生一次生产许可/Run/outbox；未知先查原单，不盲建第二单。用户调整未付方案先令旧确认/报价失效并查清旧单状态；旧单UNKNOWN不能当未付失败。晚付款记入原单，按可履行原合同或原路退，不覆盖新单。

## 结果与清理

付款后Agent生成批量九文件，经独立验证、复制独立结果存储、hash/readback与持久提交，原子发布result pointer和清理outbox。随即释放Agent并销毁任务环境，结果文件继续保留。结果可领取不等于平台已认可履约，FETCHED/CACHED不能一概充实际导出。

保存失败不能先销毁唯一材料；在授权预算内恢复，否则按合同失败/原路退款。0候选不捏造行；若已付按原承诺退。结果已可靠保存但清理失败，结果可用、清理重试告警，不能重跑收款。订单与清理最小凭据独立于客户上下文留存；不为售后无限保存整个源环境。

## 修订与保留

产出后环境已销毁，调整从新session完整预载开始，用户选择父结果及必要重传原件，再分析/确认/估费。原合同平台纠错可核原实付权益覆盖，新增需求按新报价实付；不伪造免费通道流水或复活旧container。

结果不因流程结束、短链TTL或旧7天候选被自动删除；下载按owner/结果权限重新签链。私有规范仅用户主动另存的去事实版本独立保留。原始输入、会话正文、中间文件和任务日志随container清理；结果内必要出处摘录属于结果，不保留隐藏完整原件副本。

## 对账与外部证据

支付/退款按原平台原单位分别记账，验商户/app/订单/金额；不混算虚拟单位。外部提交未知按原请求查，退款申请不等于到账；并发/晚到/重复/响应丢失需真实故障证据。平台主体/类目/规则/SDK/退款和计价参数均未实证，当前所有生产收费开关关闭。

## 实施细则

## 上线资格与金额

收费开关按 provider + app_alias + OS + SKU + build + policy_version 生效，要求主体/类目/商品/支付/退款/交付/数据政策真实证据通过。抖音 iOS 当前官方入口已一致，仍不代表本 app/SKU 有权限；沿用[官方复核](../资料/双小程序官方能力复核-v3.1-2026-10-27.md)。未开通不显示假收银，不引导外站绕支付。消费者普通支付不自动构成赛事 AI 付达标，Machine Pay/A402 为 P1 独立接入。

quote 固定 contract_hash、原始 amount_minor/amount_unit/provider/SKU、expiry、范围/预算、交付、修订/退款/期限 policy_snapshot 与 capability_version。金额由服务端定价，客户端不能传新价格。平台虚拟单位原样展示和记账，不能按自造汇率宣传人民币收入。



## 乱序、晚到与付款历史

payment 轴 CONFIRMED 是已付历史，不通过退款改回未付。CLOSED/FAILED 仍可能收到真实晚付/通道纠正，验真后允许 CONFIRMED、记录异常，再按原合同履约或原路退款；不能丢掉已经收到的钱，也不能默认复活已取消/删除的任务。

订单金额不符、单位不符、app/商户不符进入安全/运营隔离，不发 grant。查单与回调并发锁同 order + fact_key，ledger 只追加一次；不通过全局“订单已处理”字符串粗暴吞掉退款后续事件。

退款轴、履约轴、取用观察分开。DELIVERABLE 为原合同可取用服务/文件，DELIVERED 需适用获准商品交付证据；打开文件/用户缓存不能一概充官方履约。付费服务不能履行时按合同原路退款，不把客户拖到无限“处理中”。



## 退款原子额度与未知结果

refunds 记录原 order/provider_payment_ref、merchant_refund_ref、amount_minor/unit、reason、status、retry_of。提交事务锁 order，核实付减已成功/在途预留 ≥ 本次退款，预留额度并 outbox。对原退款未知时重查同 merchant_refund_ref，不能创建第二个退款单释放后再退一次。

通道确定接收→PROCESSING；未知→UNKNOWN；正式确认→SUCCEEDED/FAILED。SUCCEEDED 追加唯一 ledger，释放对应预留并累计退款；累计不能超过原实付。FAILED 确定后新尝试需要 retry_of、重新核额度与原因；原 Operation 终态保留。

用户未导出、源内容缺失、平台漏识别、执行预算失败、九文件损坏、零候选、取消竞态、删除/注销对已售单的影响按 policy_snapshot 判定，不把“付过钱”当所有场景都不可退。零有效候选不能以诊断包充严格成表交付，按需求全额原路退/售后。平台纠错免费且不扣用户修订轮次。



## 对账和履约补偿

每次回调/查单保存受控 provider fact 和摘要；每日对账按原单位逐订单核本地实付/退款/通道账单/履约。UNKNOWN 工程候选10分钟进入运营列表，查单频率遵守真实通道限流，不能把候选写成外部承诺。

对账差异类型：通道已付本地无单、金额/单位不符、重复/漏退款、晚支付、实付无 grant/job、交付损坏、账单/手续费差异。每差异分配 ticket/责任/截止候选，修复仍走幂等业务 service，不能直接 SQL 把状态改成功。

成本按 quote/contract/run/stage/attempt 汇总 OCR、模型、失败/重试/修订、流量/产物、支付费/退款和客服。贡献=实收−退款−可归属变动成本，不等于净利润。外部币种/虚拟单位未证实换算时分账报告，不混合汇总。



## 必须完成的真实测试

沙箱可测字段/签名/幂等路径，但正式资格和实际原路退款要另留证据。至少覆盖重复/并发/乱序回调、回调丢失查单、客户端取消但实付、金额单位错、关单后晚付、退款提交超时、退款已退响应丢失、重复申请、免费与付费许可隔离、支付后删除/发布竞态。

测试资金仅使用获准测试配置和明确测试订单；无真实流水不能写 PASS。高风险差异暂停受影响新收单，保留原订单查询、退款/售后和必要恢复；恢复收费须资金事实闭合与负责人复核。

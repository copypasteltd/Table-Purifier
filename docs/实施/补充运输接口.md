# 实际补充运输接口

冻结业务 API 仍为 `assets/development/v3.0.0/openapi.json` 的 56 项，不覆写其历史状态。本文件记录实际源码为小程序和受控运营补上的接缝。根前缀 `/transport/v1`，健康接口除外；实现位置为 `src/api/server.ts`、`src/api/correction-routes.ts`。

普通 JSON 成功返回 `{request_id,data}`，错误返回 `{request_id,error:{code,message,retryable}}`。上传成功返回裸 `{upload_id,observed_bytes,observed_sha256}`，下载成功返回二进制，平台回调按原平台 ACK 返回。任何地方不返回真实密钥、原始 SQL 或异常堆栈。

普通读取/业务写入使用我方登录 `Authorization: Bearer <opaque-login-token>`。上传使用单次限域上传 token，下载使用短期签名 token，运营接口使用独立运营 bearer。业务 POST 需要 `Idempotency-Key`（16～128 字符）。普通用户不能用客户端字段指定 owner 或运营身份。

| 方法与路径 | 输入与输出 | 关键约束 |
| --- | --- | --- |
| `GET /health/live` | `{status:alive}` | 无客户内容，进程存活 |
| `GET /health/ready` | ready 或 503 unavailable | 数据库迁移名称、数量、逐份摘要完全一致 |
| `POST /transport/v1/uploads/:upload_id` | multipart 唯一 `file`；输出实际字节数/摘要 | 仅授权会话、READY 后可接收；限制大小/内容摘要；额外 part 拒绝且不提交 RECEIVED |
| `GET /transport/v1/downloads/:grant_id?token=...` | 二进制文件 | 绑定 owner/结果/单文件/期限、撤销检查、重新 hash、受限 Range |
| `GET /transport/v1/tasks/:task_id/plan` | `{plan,binding_id,contract_id,contract_hash,order_id}` | 只读当前任务方案；解决冻结 API10 所需 plan 标识在读取模型缺失的问题 |
| `GET /transport/v1/orders/:order_id/context` | `{task_id,session_id,run_id}` | 历史订单恢复正确任务，避免沿用小程序旧状态 |
| `GET /transport/v1/runs/:run_id/schema?result_version=N` | `{result_version,schema}` | 使用独立保留的结果规范，不读取已销毁的分析草案 |
| `POST /transport/v1/runs/:run_id/rework-sessions` | Request54；输出 `{session_id,status,operation_id}` | 先建立新会话和完整预载，尚不接收修改正文；初始化中可重复查询/重入 |
| `POST /transport/v1/runs/:run_id/correction-sessions` | 同上 | 新建原单纠错会话；检查原实付订单、平台和退款/对账状态 |
| `GET /transport/v1/tasks/:task_id/correction` | `{is_correction,parent_run_id?,authorization?}` | 当前方案的运营审核状态，不能跨 owner 或读取已删除任务 |
| `POST /transport/v1/corrections/:authorization_id/runs` | `{session_id,contract_id,plan_hash,quote_id}`；输出 Run | 精确批准的新方案、有效估费、原实付权益、剩余累计预算；不新收款、不复活旧会话 |
| `POST /transport/v1/data-deletion-requests/:request_id/retry` | `{}`；输出 DeletionJob | 同 owner、既有失败请求；重置失败队列/清理任务，不恢复任何业务访问 |
| `GET /transport/v1/operator/tasks/:task_id/review?owner_id=UUID&ticket_id=UUID` | 当前方案/资料范围摘要、分析内容及售后说明 | 独立运营 token；用户对具体当前任务的有效限时售后授权；清理后内容不可凭空恢复 |
| `POST /transport/v1/operator/corrections` | 下述审核 DTO；输出纠错授权 | 有效售后授权、真实原单实付权益、重传原件摘要、当前确认合同/方案/估费、原预算 |

Request54 的正文仅为：

```json
{"client_request_id":"UUID","skill_release_id":"UUID"}
```

不得附带目标、文本、文件、标准表、修订值或售后说明。READY 后才按既有 03/06/07/24/25 等接口提交。

运营审核 DTO：

```json
{
  "owner_id": "UUID",
  "ticket_id": "UUID",
  "parent_run_id": "UUID",
  "contract_id": "UUID",
  "plan_hash": "64位小写SHA256",
  "reason_code": "OMITTED_FIELD",
  "review_receipt_ref": "internal/reviews/已实际审查记录的标识"
}
```

reason_code 仅 `OMITTED_FIELD` 或 `EXTRACTION_ERROR`。审核记录引用只接受限定字符，不携带客户正文。用户必须在当前新任务建立售后单并明确同意限时核对；默认授权最多 24 小时。运营审批本身不能替代真实模型、设备或支付验收。

纠错授权读取输出：`authorization_id`、`original_order_id`、`status`（APPROVED/USED/REVOKED/EXPIRED）、`expires_at`、`used_run_id`。重复启动已使用授权返回同一子 Run；原单退款/对账异常、方案变化、过期估费或预算耗尽均阻断。新合同在用户确认时就绑定原预算根，后续运营审核不修改不可变合同。

下载链接发放仍通过冻结 API29，其正文必须含 `expected_result_version`；运输下载不接受 owner 参数。客户端领取回执只能记录 FETCHED/OPEN_REQUESTED/OPENED/USER_CONFIRMED 等观察，不能声称平台确认送达或核实付款。

支付事件接口是冻结 API53 的实际原始报文处理器：`POST /v1/p07/platform-events/:provider`，保留原始字节进行验签，不能通过普通 JSON 重序列化替代。业务付款状态仍由服务端查询/验签确认；客户端支付回调不放行批量。

常见阻断：401 未登录/令牌失效，403 越权用途或缺少同意/原实付权益，404 当前 owner 不可见，409 版本/阶段/幂等冲突，410 正文或领取许可已清理，413 大小或 multipart 数量限制，429 流量/预算，503 配置或可信能力未满足。P1 未开放接口为明确 501。
